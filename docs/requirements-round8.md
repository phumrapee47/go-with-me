## รายละเอียด User Stories & Acceptance Criteria

### BUG-1: Duplicate keys crash ตอนค้นหาสถานที่ปลายทาง [P0]
As a ผู้ใช้ที่กำลังสร้างทริป,
I want พิมพ์ค้นหาสถานที่ปลายทางแล้วเห็นรายการผลลัพธ์ที่ถูกต้อง แม้ผู้ให้บริการค้นหา (Nominatim) จะส่งผลลัพธ์ซ้ำกลับมา,
so that ฉันสามารถเลือกสถานที่และสร้างทริปต่อได้โดยไม่ต้องรีสตาร์ทแอป

**สาเหตุที่พบ:** widget list ใช้ key ที่มาจากค่าที่ Nominatim ส่งกลับ (เช่น `place_id`/string) โดยไม่ dedup ก่อน render ทำให้ Flutter เจอ key ซ้ำใน `Column` แล้ว crash

#### Acceptance Criteria:
- [ ] เมื่อผลการค้นหาจาก autocomplete มีรายการที่ key ซ้ำกัน (จงใจ mock response ให้ซ้ำในเทสต์) แอปต้อง **ไม่ crash**
- [ ] รายการที่แสดงผลต้อง **ไม่มีรายการซ้ำ** (dedup ตามตัวระบุสถานที่ที่เหมาะสม ก่อนส่งเข้า widget tree)
- [ ] Regression: การค้นหาปกติ (ไม่มีผลซ้ำ) ยังทำงานถูกต้องเหมือนเดิม ไม่มีรายการหายไปโดยไม่ตั้งใจ

### BUG-2: ANR ตอนกดปุ่ม "ใช้ตำแหน่งปัจจุบัน" [P0]
As a ผู้ใช้ที่กำลังตั้งจุดเริ่มต้นของทริป,
I want กดปุ่ม "ใช้ตำแหน่งปัจจุบัน" แล้วได้ผลลัพธ์หรือ error ภายในเวลาอันสมควร แม้อุปกรณ์หรือ GPS จะตอบสนองช้า,
so that แอปไม่ค้างและฉันสามารถลองใหม่หรือใช้วิธีอื่นแทนได้

**สาเหตุที่พบ:** การเรียกขอตำแหน่ง (location request) ไม่มี timeout และดูเหมือนรันแบบบล็อก UI thread เมื่อ location service ตอบช้าหรือไม่ตอบเลย ทำให้ทั้งแอป ANR

#### Acceptance Criteria:
- [ ] การขอตำแหน่งต้องมี timeout ที่กำหนดไว้ชัดเจน (ระบุค่าที่เหมาะสม เช่น ไม่เกิน 10-15 วินาที) หากเกินเวลาต้องยกเลิก request และแสดง error message ให้ผู้ใช้กดลองใหม่ได้
- [ ] ระหว่างรอผลตำแหน่ง **UI ต้องไม่ค้าง** — ผู้ใช้ยังสามารถกดปุ่มอื่น (เช่น ยกเลิก, กลับหน้าก่อนหน้า) ได้ตามปกติ
- [ ] กรณี location permission ถูกปฏิเสธหรือ service ปิดอยู่ระหว่างที่รอ ต้องแสดง error ที่สื่อความหมายทันที ไม่ปล่อยให้ค้างเฉยๆ
- [ ] Regression: กรณีปกติที่ GPS ตอบเร็ว ต้องได้ตำแหน่งและกรอกข้อมูลจุดเริ่มต้นถูกต้องเหมือนเดิม

### BUG-3: Validation "เลือกจุดเริ่มต้น" ค้างหลังปักหมุดบนแผนที่ [P0]
As a ผู้ใช้ที่กำลังสร้างทริป,
I want ปักหมุดจุดเริ่มต้นผ่าน "ปักหมุดบนแผนที่" แล้วให้สถานะ validation อัปเดตทันทีตามข้อมูลจริงในช่อง,
so that ฉันกดปุ่ม "ถัดไป" แล้วไปหน้าถัดไปได้โดยไม่ติดขัด

**สาเหตุที่พบ:** flow "ปักหมุดบนแผนที่" อัปเดตค่าที่อยู่ในช่องข้อความ (text field) แต่ไม่ได้อัปเดต state/flag ที่ใช้เช็ค validation ของฟอร์ม (ต่างจาก flow พิมพ์ค้นหา หรือ GPS ที่อัปเดต flag ถูกต้อง) ทำให้ error message ค้างอยู่ทั้งที่ข้อมูลถูกต้องแล้ว

#### Acceptance Criteria:
- [ ] เมื่อปักหมุดจุดเริ่มต้นผ่าน "ปักหมุดบนแผนที่" สำเร็จ ข้อความ error "เลือกจุดเริ่มต้น" ต้อง **หายไปทันที** โดยไม่ต้องแตะช่องอื่นหรือรีเฟรชหน้า
- [ ] หลังปักหมุดจุดเริ่มต้นถูกต้องแล้ว (และปลายทางถูกต้องอยู่ก่อนแล้ว) กดปุ่ม "ถัดไป" ต้อง **นำทางไปหน้าถัดไปได้สำเร็จ**
- [ ] Regression: validation ยังคงทำงานถูกต้องสำหรับอีก 2 flow เดิม (พิมพ์ค้นหา, ใช้ตำแหน่งปัจจุบัน) และยังคงแสดง error หากผู้ใช้ยังไม่ได้เลือกจุดเริ่มต้นเลย

## Out of Scope (รอบนี้)
- ไม่ออกแบบ UI ใหม่หรือเปลี่ยน UX flow ของหน้าสร้างทริป
- ไม่เปลี่ยนหรือเพิ่ม schema ฐานข้อมูล
- ไม่เพิ่ม endpoint หรือ third-party service ใหม่
- ไม่ครอบคลุมบั๊กอื่นนอกเหนือจาก 3 รายการนี้ แม้จะพบระหว่างการทดสอบ (ให้บันทึกแยกไว้สำหรับรอบถัดไป)
- ไม่ปรับปรุง performance ของ location service หรือ search service ในภาพรวม นอกเหนือจากขอบเขตที่ระบุไว้เพื่อแก้บั๊กนี้โดยเฉพาะ
