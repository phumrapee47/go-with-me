
# Design Spec รอบ 6: Friendly & Frictionless Commute UX (ส่วนต่อของ design-spec.md)

ขอบเขต: US-29..US-41 ตาม `docs/requirements-round6-ba.md` (ไม่แก้ `docs/design-spec.md`)
ลำดับความสำคัญ: เอกสารนี้ "ทับ" เฉพาะที่ระบุ (หน้า active trip S-21, live map S-37 ในแง่การจัดวาง, nearby S-13 ในแง่รูปแบบ, การ์ดหน้าแรก S-09) ส่วนที่ไม่กล่าวถึงใช้ตาม design-spec.md (token 1.x, D.1 สอง โทน, E-1..E-14 รอบ 5)
ข้อความที่อ้างอิง token: ใช้ชื่อ semantic ของ D.1 (rider.* / driver.*) ไม่กำหนดค่าใหม่ ยกเว้นที่ระบุว่า "ใหม่"

## 0. หลักการรอบ 6
- ลดจำนวนแตะและ dialog ซ้ำ แต่ไม่ลดความปลอดภัย: SOS เด่นและเข้าถึงได้ทุกระดับ sheet, การกระทำย้อนกลับไม่ได้ (ขึ้นรถ/ถึง/เริ่ม) ยังต้องมี "ความตั้งใจ" (สไลด์หรือกดค้าง) ไม่ใช่แตะครั้งเดียว
- ทุกท่าทาง (ปัด, สไลด์, ลาก sheet) ต้องมีทางเลือกแบบแตะ/กดค้าง/semantics action ที่ให้ผลเท่ากัน
- ห้ามพึ่งสี/emoji/แอนิเมชันอย่างเดียวในการสื่อความ; reduce motion ให้ผลเท่ากันแบบไม่เคลื่อนไหว
- ความเป็นส่วนตัว: การ์ด deck ไม่มีรูปจริง/ปลายทางจริง/พิกัด; preset บ้านเก็บในเครื่องเท่านั้น; geofence คำนวณบนเครื่องจากปลายทางของตนเอง
- โทน: หน้า Unified, deck, Match Moment เป็น trip-bound (ตาม role ของทริปนั้น ผ่าน TripToneIsland/D.2); การ์ดหน้าแรกและหน้า preset เป็น app-level (ตาม active role)
- ไอคอนของปุ่ม ✕ / 💚 ใช้ไอคอนเวกเตอร์ชุดเดียวกับแอป + ข้อความกำกับเสมอ; emoji ใช้เฉพาะในข้อความ (ดู F.8)

## F.1 Design tokens เพิ่มเติม (ทั้ง 2 โทน; ใช้ค่าจาก D.1 เท่านั้น)
| ส่วน | Rider (สว่าง) | Driver (deep navy + amber) |
|---|---|---|
| พื้น sheet | rider.surface, มุมบน radius 24, เงากลาง | driver.surface-raised, มุมบน 24, เงากลาง + ขอบบน 1 dp driver.border |
| ที่จับ (handle) | 40x4 dp, rider.border-strong | 40x4 dp, driver.border-strong |
| ข้อความ | rider.text / text-secondary | driver.text / text-secondary |
| แถบสไลด์: พื้นราง | rider.primary-tint + ขอบ 1.5 dp rider.primary | driver.surface + ขอบ 1.5 dp driver.border-strong |
| แถบสไลด์: ปุ่มจับ (thumb) | พื้น rider.primary ไอคอนขาว | พื้น driver.amber ไอคอน driver.on-amber |
| แถบสไลด์: ส่วนที่ลากผ่าน (fill) | rider.primary opacity 20% | driver.amber opacity 25% |
| แถบสไลด์: โหมดใกล้ถึง (geofence) | ราง rider.mint ขอบ 2 dp green-dark #0E7A57, thumb rider.success-fill ขอบ green-dark 2 dp ไอคอน navy | ราง driver.surface + fill driver.success 22% ขอบ 2 dp driver.success, thumb driver.success ไอคอน #0B1B33 |
| ปุ่มชวน (💚) | พื้น rider.success-fill ตัวอักษร/ไอคอน navy | พื้น driver.success ตัวอักษร/ไอคอน #0B1B33 |
| ปุ่มข้าม (✕) | ปุ่มขอบ rider.border-strong ไอคอน rider.text | ปุ่มขอบ driver.border-strong ไอคอน driver.text |
| Stamp "ชวน" บนการ์ด | พื้น rider.success-fill + ข้อความ navy | พื้น driver.success + ข้อความ #0B1B33 |
| Stamp "ข้าม" บนการ์ด | พื้น rider.surface ขอบ rider.border-strong ข้อความ rider.text | พื้น driver.surface-raised ขอบ driver.border-strong ข้อความ driver.text |
- ตรวจ contrast ที่ต้องเพิ่มใน golden test: navy บน mint 13.7 (ผ่านแล้ว D.1.3); ตัวอักษรบน fill 20-25% ต้อง >= 4.5:1; ขอบ green-dark บน mint >= 3:1; driver.success ขอบ บน driver.surface 8.5 (ผ่าน)
- แผนที่ยังเป็น tile สว่างทั้ง 2 โทน (ไม่มี dark map ใน scope): sheet ของ Driver เข้มวางทับแผนที่สว่างได้ เพราะ sheet มีเงา + ขอบบน

## F.2 User Flow

### User Flow: US-29 / US-30 หน้าเดินทางรวม UnifiedRideScreen (Rider)
1. ผู้ใช้เปิด `/trips/active` (จากแบนเนอร์ ActiveTripBanner, Match Moment, แจ้งเตือน, deep link เดิม) ระบบตรวจ guard แล้วเปิดแผนที่เต็มจอ + sheet ที่ระดับเริ่มต้นตามสถานะ (F.3.6)
2. ผู้ใช้เห็นแผนที่ (ตนเอง, คู่ตามสิทธิ์ US-23, จุดรับที่ตกลงแล้ว, เส้นทาง) และ sheet ระดับ Collapsed: ชื่อคู่ + สถานะ + ETA + แถบสไลด์/ปุ่มหลักของสถานะนั้น; ปุ่ม SOS ลอยมุมขวาบนเสมอ
3. ผู้ใช้ลาก sheet ขึ้น Half เห็นข้อมูลรถ (ถ้ามีสิทธิ์), จุดรับ, ชิปแชทด่วน, ปุ่มนำทาง; ลากต่อเป็น Full เห็นรายละเอียดทริป แชร์ทริป แชท
4. ผู้ใช้แตะชิปแชทด่วน: sheet ขยายเป็น Full, ข้อความไปอยู่ในช่องพิมพ์ (ไม่ส่งอัตโนมัติ) และโฟกัสช่องพิมพ์
5. เมื่อคนขับมาถึง/ผู้ใช้ถึงจุดรับ: แถบสไลด์ "ขึ้นรถแล้ว" ไฮไลต์เขียวเมื่อ < 150 ม. (F.4.7); ผู้ใช้สไลด์ครบ -> ระบบเรียก RPC เดิม -> success -> สถานะเปลี่ยนเป็นบนรถ (ข้อความ "ขึ้นรถเรียบร้อยแล้ว")
6. เมื่อถึงปลายทาง ผู้ใช้สไลด์ "ถึงบ้านปลอดภัย" -> หน้าเปลี่ยนเป็นสถานะ Arrived (F.3.5)
7. ที่ทุกขั้น ผู้ใช้กด SOS ได้ในการแตะครั้งเดียว (เปิด SosSheet C-19 ที่มีขั้นยืนยันกันกดพลาดเดิม) ภายใน <= 2 แตะรวมการยืนยัน; ไม่ต้องขยาย sheet

### User Flow: US-29 / US-30 หน้าเดินทางรวม (Driver)
1. ผู้ใช้เปิด `/trips/active` ในโทน Driver (navy + amber) เห็น Collapsed: ชื่อ Rider + สถานะ "กำลังไปรับ" + ETA ไปจุดรับ + ปุ่มหลัก
2. ก่อนรับ: ปุ่ม "ถึงจุดรับแล้ว" (F-6) เป็นปุ่มหลักใน Collapsed (ดู C-4 ใน F.9) กดครั้งเดียว -> ข้อความ "คนขับมารอที่จุดรับแล้วนะ" ไปที่แชท Rider
3. เมื่อ Rider ขึ้นรถ: Driver เห็น "คนนั่งขึ้นรถแล้ว ระบบหยุดแสดงตำแหน่งของเขาแล้ว" (ข้อความเดิม R5); ปุ่มหลักเป็นแถบสไลด์ "สไลด์เมื่อถึงบ้านปลอดภัย"
4. Half/Full: ไม่มีข้อมูลรถ (ของตนเอง) ในฐานะ "คู่"; ไม่มีปลายทางของ Rider; ปุ่มนำทางไปจุดรับ/ปลายทางของตนเองเท่านั้น
5. SOS เหมือน Rider ทุกประการ (แดงเดิม ขอบขาว 2 dp ตาม D.1.3)

### User Flow: US-31 / US-32 สไลด์ยืนยันการเปลี่ยนสถานะ
1. ผู้ใช้เห็นแถบสไลด์ (รางยาว + thumb ซ้าย + ข้อความบอกการกระทำ)
2. ผู้ใช้วางนิ้วที่ thumb ลากไปขวา: fill ตามนิ้ว, ข้อความจางลง; sheet ลากไม่ได้ขณะนิ้วอยู่บน thumb
3. (ทางแยก ก) ปล่อยก่อนสุดราง -> thumb เด้งกลับซ้าย ไม่เรียก RPC ไม่มี dialog
4. (ทางแยก ข) ลากถึงปลายราง (>= 95%) -> haptic ยืนยัน, thumb ล็อกที่ปลาย, ระบบเรียก RPC/อัปเดตสถานะเดิมครั้งเดียว (แถบเข้าสถานะ submitting; ลากซ้ำไม่ได้)
5. สำเร็จ: thumb เป็นเครื่องหมายถูก + ข้อความเรียบร้อย -> หน้าเปลี่ยนสถานะ (Collapsed อัปเดต)
6. ล้มเหลว: แถบกลับสถานะเริ่มต้น, ข้อความไทยเหนือแถบ (role=alert) พร้อมเหตุผลและ "สไลด์ใหม่ได้เลย"
7. (ทางเลือกเข้าถึงได้) ผู้ใช้กดค้างที่รางหรือ thumb 1.5 วินาที: วงแหวน/แถบความคืบหน้าเต็ม -> ผลเท่ากับข้อ 4; ผู้ใช้ screen reader เลือก custom action "ยืนยัน..." ในเมนู actions ผลเท่ากัน
8. เมื่อ GPS ระบุว่าอยู่ห่างจากจุดหมายของตนเอง < 150 ม. รางเปลี่ยนเป็นเขียว + ข้อความ "ใกล้ถึงแล้ว" (ไม่เปลี่ยนสถานะเอง ไม่ปลดล็อก/ล็อกอะไร)

### User Flow: US-33 คนขับแจ้งถึงจุดรับ
1. Driver (ทริป car ที่จับคู่ตอบรับแล้ว + จุดรับตกลงแล้ว + Rider ยังไม่ขึ้นรถ) เห็นปุ่ม "ถึงจุดรับแล้ว" ใน Collapsed
2. ผู้ใช้แตะครั้งเดียว: ปุ่มเข้าสถานะ sending (ปุ่มปิดชั่วคราว) -> ส่งข้อความเดิมช่องทางแชท
3. สำเร็จ: ปุ่มเปลี่ยนเป็น "ส่งแล้ว" (ไอคอนถูก) ปิดใช้ 60 วินาทีพร้อมนับถอยหลังข้อความ ("ส่งซ้ำได้ใน 45 วินาที" อัปเดตทุก 5 วินาทีเพื่อไม่ให้ screen reader อ่านถี่); จากนั้นกลับปกติ
4. Rider เห็นข้อความในแชท + แจ้งเตือนในแอป และแถบสถานะ Collapsed เปลี่ยนเป็น "คนขับมารอที่จุดรับแล้วนะ"
5. ล้มเหลว: snackbar "ส่งไม่สำเร็จ ลองอีกครั้ง" ปุ่มกลับปกติ
6. ปุ่มหายเมื่อ Rider ขึ้นรถ/การจับคู่สิ้นสุด

### User Flow: US-34 / US-35 / US-36 การ์ดเพื่อนร่วมทาง
1. ผู้ใช้ (มีทริปที่ใช้งานได้) เปิด `/nearby` เห็น skeleton การ์ด (loading) แล้วการ์ดใบแรก + เงาการ์ดใบถัดไปด้านหลัง
2. ผู้ใช้อ่านการ์ด: ตัวอักษรย่อ+ชื่อเล่น, ป้าย, ทางเดียวกัน ~N%, เวลา, บทบาท (Driver: รับได้ 1 คน · ไม่เกิน X จากปลายทางของเขา), คะแนน (ถ้า >= 3 รีวิว)
3. (ก) ปัดซ้ายหรือกด ✕ "ข้าม": การ์ดหลุดซ้าย (180 ms) -> การ์ดถัดไป; ไม่มีข้อความถึงอีกฝ่าย; ประกาศ screen reader "ข้าม <ชื่อ> แล้ว การ์ดถัดไป <ชื่อ>"
4. (ข) ปัดขวาหรือกด 💚 "ชวนกลับด้วยกัน": การ์ดหลุดขวา -> snackbar "กำลังชวน <ชื่อ>..." + ปุ่ม "เลิกชวน" 5 วินาที (ดูข้อเสนอ P-3) -> ครบเวลา/ส่งสำเร็จ -> snackbar "ชวนเพื่อนแล้ว! รอเพื่อนตอบแป๊บนะ"
5. (ค) ผู้ใช้กด "เลิกชวน" ภายใน 5 วินาที: ยกเลิกคำขอ การ์ดกลับมาด้านหน้า ประกาศ "เลิกชวน <ชื่อ> แล้ว"
6. (ง) ปัดขวาแต่คำขอค้างเต็มเพดาน: การ์ดเด้งกลับ + ข้อความไทยอธิบาย ไม่ส่ง
7. แตะตัวการ์ด/ "ดูรายละเอียด" -> S-14 (push); กลับมาที่การ์ดเดิมตำแหน่งเดิม
8. การ์ดหมด -> หน้าสรุป "ดูครบทุกคนแล้ว" + ทางไปรายการ/คำขอที่ชวนไว้/แก้ทริป/รีเฟรช
9. ผู้ใช้สลับ "รายการ" ที่ segmented control ด้านบน -> เห็นรายการ nearby เดิม (S-13) (จำค่าที่เลือกในเครื่อง)

### User Flow: US-37 Match Moment
1. ระบบพบว่าการจับคู่เปลี่ยนเป็น "ตอบรับแล้ว" และผู้ใช้ยังไม่เคยเห็นโมดอลของ match นี้ (ตรวจ flag ในเครื่อง)
2. โมดอลเปิดทับหน้าปัจจุบัน (focus ย้ายเข้าหัวข้อ, ประกาศ "ได้เพื่อนกลับบ้านแล้ว")
3. ผู้ใช้เลือก "ทักทายนัดจุดรับ" -> เปิดแชทของ match พร้อมข้อความทักทายในช่องพิมพ์ (ยังไม่ส่ง)
4. หรือ "ดูแผนที่การเดินทาง" -> `/trips/active`; ถ้ายังไม่เข้าเงื่อนไข -> `/matches/:matchId` + snackbar สุภาพ
5. หรือปิด (X/แตะนอก/back) -> กลับหน้าเดิม, focus กลับจุดเริ่ม; ตั้ง flag ว่าเห็นแล้ว (ทุกทางออกนับว่าเห็นแล้ว)
6. ถ้าการจับคู่ถูกยกเลิกก่อนโมดอลแสดง: ไม่แสดง

### User Flow: US-38 ตั้งสถานที่โปรด
1. ผู้ใช้กด "ตั้งค่าสถานที่โปรด" จากการ์ดหน้าแรก (สถานะขาด preset) หรือจาก /me > "สถานที่โปรด"
2. ครั้งแรก: เห็นแผ่นแจ้ง "เก็บไว้ในเครื่องนี้เท่านั้น" -> กด "เข้าใจแล้ว ไปต่อ"
3. ขั้น "บ้าน": ค้นหา/ปักหมุด + ตั้งชื่อ -> ต่อไป
4. ขั้น "จุดเริ่มประจำ": เลือกประเภท (ที่ทำงาน/มหาวิทยาลัย/อื่นๆ) + สถานที่ + ชื่อ -> ตรวจ (ไม่ซ้ำบ้าน)
5. สรุป: 2 แถว พร้อมแก้/ลบ -> "เสร็จ" -> กลับหน้าแรก เห็นการ์ดกลับบ้าน 1 แตะ
6. ลบ: กด "ลบ" -> ConfirmDialog (C-23, ใช้ dialog เดิม) -> ลบจริงจากเครื่อง

### User Flow: US-39 การ์ดกลับบ้าน 1 แตะ
1. ผู้ใช้เปิด /home (มี preset ครบ, ไม่มีทริปที่ใช้งาน) เห็นการ์ด "กำลังจะกลับบ้านใช่ไหม?"
2. เลือกเวลา (ชิป), บทบาท (คนนั่ง/ขับรถเอง จำค่าล่าสุด); ถ้า Driver เห็นแถวระยะรับส่ง (ค่าเริ่มต้น 2 กม.) ปรับได้
3. กด "หาเพื่อนกลับบ้าน": ปุ่ม loading -> ระบบสร้างทริปด้วย validation เดียวกับ wizard
4. สำเร็จ -> `/nearby` (deck) ของทริปนั้นทันที
5. validation ไม่ผ่าน/มีทริปที่ใช้งานอยู่/Driver ไม่พร้อม -> ข้อความไทย + ปุ่ม "ไปตั้งทีละขั้น" เปิด wizard S-10 พร้อมค่าที่กรอกไว้ (หรือพาไปทริปเดิมถ้ามีทริปที่ใช้งานอยู่)
6. preset ไม่ครบ -> การ์ดสถานะ "ตั้งบ้านไว้ แล้วกลับบ้านได้ในแตะเดียว" + ปุ่ม "ตั้งค่าสถานที่โปรด" และ "สร้างทริปเอง" (wizard)

### User Flow: US-40 / US-41 ข้อความและเส้นทาง
1. ข้อความ 5 รายการเปลี่ยนตาม F.8; emoji มี semantics
2. `/trips/active`, `/matches/:id/live`, `/trips/:tripId/active` ถูกชี้ไป UnifiedRideScreen (F.10)

## F.3 UnifiedRideScreen

### F-1 UnifiedRideScreen (โครงหน้า)
- Purpose: หน้าเดียวสำหรับทริปที่กำลัง/ใกล้ดำเนินการ แทน S-21 active trip, S-37 live map และแชท (แชทอยู่ใน sheet)
- Layer (ล่าง -> บน): (1) LiveMapView E-7 เต็มจอ (2) ปุ่มควบคุมแผนที่ E-12 (คอลัมน์ขวา ยึดกับขอบบนของ sheet ห่าง 12 dp, ซ่อนเมื่อ Full) (3) RideSheet F-2 (4) RideTopOverlay F-3 (ปุ่มย้อน, ปุ่มดูแบบข้อความ, SOS) เหนือ sheet ทุกระดับ
- ห้ามบัง: SOS ไม่ถูก sheet/แป้นพิมพ์/แถบสไลด์บัง (อยู่ขอบบน ไม่ขึ้นกับความสูง sheet)
- States: loading (พื้นแผนที่เทา + sheet skeleton: แถวคู่ 1 แถว + แถบสไลด์ disabled; SOS ใช้ได้ทันที) / ready / no-peer (ทริปเดี่ยว/Peer: sheet ไม่มีแถวคู่ ไม่มีแชท ไม่มีข้อมูลรถ; แสดงจุดหมาย+ETA แทน) / peer-ended (MatchEndNotice C-37 ใน Collapsed, ไอคอนคู่หายทันที) / offline (OfflineBanner C-5 ใต้ top overlay; แถบสไลด์ "ถึงแล้ว" ทำงานได้แต่ถ้าส่งไม่ได้ให้ error ชัดเจน) / permission-denied (E-7) / tiles-error (E-7) / guard-failed (redirect พร้อม snackbar กลาง)
- Responsive: หน้าจอกว้าง 390 dp ใช้งานได้; text scale 200% -> sheet Collapsed ขยายความสูงตามเนื้อหา (ไม่ fix)

### F-2 RideSheet (DraggableScrollableSheet 3 ระดับ)
- Purpose: พื้นที่ข้อมูล/แชท/การกระทำของทริป ลากได้ 3 ระดับ
- ขนาด (dp บนหน้าจอสูง H, safe area บน T):
  - Collapsed: ความสูง = ความสูงเนื้อหา (ประมาณ 200 dp ที่ scale 100%: ที่จับ 24 + แถวคู่ 56 + ช่องว่าง 12 + แถบสไลด์ 64 + padding ล่าง 12 + safe area ล่าง); ขยายตามข้อความใหญ่ ไม่เกิน 40% ของ H
  - Half: 52% ของ H (ต่ำสุด 360 dp)
  - Full: H - T - 72 dp (เหลือแถบแผนที่/ปุ่มบนสูง 72 dp เพื่อให้ SOS และปุ่มย้อนไม่ถูกบัง)
- ที่จับ: พื้นที่แตะ 48 dp กว้างเต็ม sheet ส่วนที่เห็น 40x4 dp; แตะที่จับวนระดับ Collapsed -> Half -> Full -> Collapsed; semantics: ปุ่มชื่อ "แผ่นข้อมูลการเดินทาง" ค่า "ระดับย่อ/ครึ่ง/เต็ม" พร้อม custom action "ขยาย" / "ย่อ"
- ลากแล้วสแนปตามความเร็ว/ระยะ (ปล่อยเกิน 1/3 ของช่วงถัดไปสแนปไประดับนั้น); ขณะลากเนื้อหาข้างในไม่เลื่อน จนกว่าถึง Full (เหมือนพฤติกรรม DraggableScrollableSheet: เนื้อหาเลื่อนเมื่ออยู่ Full)
- โครงภายใน: "ส่วนหัวคงที่" (ที่จับ + แถวคู่ + การกระทำหลัก) ติดบนสุดของ sheet ทุกระดับ; ส่วนล่างเลื่อนได้เมื่อ Half/Full
- จำระดับ: เก็บใน state ของหน้า (ไม่หายเมื่อหมุนจอ/กลับจากแอปนำทาง/เปลี่ยนแอปไปมา); ระดับเริ่มต้นตามสถานะ F.3.6; ไม่ขยาย/ย่อเองยกเว้น: (ก) แตะชิปแชทด่วน -> Full, (ข) เข้าสถานะ Arrived -> Half
- ขณะนิ้วอยู่บน thumb ของแถบสไลด์ (หรือกดค้างอยู่) ห้ามลาก sheet เปลี่ยนระดับ; เมื่อลากในแนวตั้งเริ่มจากแถบสไลด์ ให้ส่งต่อให้ sheet ได้ตามปกติเมื่อทิศหลักเป็นแนวตั้ง
- แป้นพิมพ์: ช่องพิมพ์แชท (ChatComposer C-17) ยึดที่ก้นของ Full เหนือแป้นพิมพ์; ถ้าความสูงที่เหลือ < 600 dp ขณะแป้นพิมพ์เปิด ให้ซ่อนแถบสไลด์ชั่วคราว (ยังเห็นแถวคู่และ SOS ตลอด) และแสดงกลับเมื่อปิดแป้นพิมพ์ ข้อความที่พิมพ์ค้างไม่หาย
- States: collapsed / half / full / dragging / keyboard-open / loading / error (แถบข้อความในเนื้อหา ไม่ทับ SOS)

#### F.3.1 เนื้อหาตามระดับ (ใช้ได้ทั้ง Rider/Driver ยกเว้นที่ระบุ)
| ระดับ | เนื้อหา (ตามลำดับบนลงล่าง) |
|---|---|
| Collapsed | (1) ที่จับ (2) แถวคู่: Avatar S 40 (รูปหลังจับคู่ตอบรับแล้ว ตามกฎ US-22 มิฉะนั้นตัวอักษรย่อ) + ชื่อเล่น + RoleBadge ขนาดเล็ก + ปุ่มแชท 48 dp (ไอคอน + ตัวเลขข้อความใหม่ + label "แชท") บรรทัดสถานะ (เช่น "กำลังมาหาคุณ") + EtaChip โดยประมาณ (E-11: มี "โดยประมาณ", fallback เส้นตรงตามเดิม) (3) การกระทำหลักของสถานะ: แถบสไลด์ F-4 หรือปุ่ม "ถึงจุดรับแล้ว" F-6 หรือแถบสถานะรอ (ตาราง F.3.4) (4) ข้อความช่วยใต้แถบ 1 บรรทัดเมื่อจำเป็น (เหตุผลที่ปิดใช้ / ข้อความ error) |
| Half | ทุกอย่างใน Collapsed + (a) VehicleInfoCard C-34 ทะเบียน/รุ่น เมื่อมีสิทธิ์ (US-17: จับคู่ตอบรับแล้ว + สวิตช์ยินยอมของ Driver; ไม่มีสิทธิ์ = ไม่แสดงและไม่มีช่องว่างว่าง) (b) PickupPointCard C-35 (ชื่อจุดรับที่ตกลงแล้ว หรือลิงก์ "ไปตกลงจุดรับ") (c) แถวชิปแชทด่วนเลื่อนแนวนอน (quick reply เดิม รวมเรื่องจุดลง) (d) ปุ่มนำทางภายนอกตามสถานะ (E-9; ปุ่มเดียวหลัก + ปุ่มรอง) (e) ข้อความสถานะแผนที่แบบข้อความ E-13 (สำหรับ screen reader) (f) ถ้าเป็นโทน Driver และยังไม่รับ: ปุ่ม "ถึงจุดรับแล้ว" ถ้าไม่ได้อยู่ใน Collapsed |
| Full | ทุกอย่างใน Half + (a) TripDetailsSection: RouteSummaryCard C-11 (ต้นทาง/ปลายทางของตนเองเท่านั้น), เวลา, วิธีเดินทาง (b) แชร์ทริป (ปุ่ม + ShareStatusBanner C-21) (c) หมวด "ความปลอดภัย": ทางเข้า SOS ซ้ำ (ไทล์ SOS เข้าที่เดียวกับปุ่มลอย) + ผู้ติดต่อฉุกเฉิน (d) ประวัติแชท (ChatBubble C-16) เลื่อนได้ + ChatComposer C-17 ยึดก้น (e) การกระทำรอง: ยกเลิก/รายงาน (ยังใช้ ConfirmDialog เดิม ไม่ใช้สไลเดอร์) |

- ไม่มีสิ่งใดของคู่นอกสิทธิ์: Driver ไม่เห็นปลายทางของ Rider; ไม่มีข้อมูลรถของทริปที่ไม่จับคู่; ทริปเดี่ยว/Peer ไม่มีแถวคู่/แชท (ส่วนนั้นถูกเอาออกทั้งบล็อก)

#### F.3.2 SOS ทุกระดับ (US-30)
- ปุ่ม SOS ใช้ C-18 เดิม (ขนาดพื้นที่แตะไม่เล็กกว่าเดิม อย่างน้อย 56 dp) ลอยที่มุมขวาบน ต่ำกว่า status bar 8 dp ห่างขอบขวา 16 dp ใน layer เหนือ sheet ทุกระดับ (Collapsed/Half/Full) ไม่เลื่อนตาม sheet และไม่ถูกแป้นพิมพ์บัง
- ทางเข้าซ้ำใน Full (ไทล์ในหมวดความปลอดภัย) ไปที่ SosSheet C-19 เดียวกัน
- แตะ SOS -> SosSheet C-19 พร้อมขั้นยืนยันกันกดพลาดเดิม (ไม่ใช้ SwipeToConfirmSlider); ออฟไลน์ยังมีโทร 191/1669
- แสดงตลอดขณะทริปของผู้ใช้ "กำลังเดินทาง" (ทั้งก่อนและหลังขึ้นรถ, ทั้งสองบทบาท); ไม่แสดงเมื่อทริปของตนเองจบแล้ว (Arrived) และในสถานะ Scheduled ก่อนเริ่มทริป (ใช้ทางเข้า /sos ใน Safety ตามเดิม) -- ดูข้อเสนอ P-8
- โทน Driver: ขอบขาว 2 dp ตามตาราง D.1.3; ขนาด/ตำแหน่งเหมือนโทน Rider
- Semantics: label "ขอความช่วยเหลือ SOS" ลำดับอ่านที่ 2 ต่อจากปุ่มย้อน (ก่อนแผนที่และ sheet)

#### F.3.3 RideTopOverlay (F-3)
- แถวบนสุด ใต้ status bar: ซ้าย: ปุ่มย้อน 48 dp (วงกลม surface + เงา, label "กลับ") และปุ่ม pill "ดูแบบข้อความ" (เปิด section E-13 ใน Half; ที่ text scale > 150% ยุบเป็นไอคอนเดียว ยังมี label semantics); ขวา: SOS
- ห่างขอบ 16 dp; ทุกปุ่มมีวงพื้น + เงาเพื่ออ่านชัดบนแผนที่ทุกสี
- ปุ่มย้อนกลับไปหน้าที่มา (ไม่ยกเลิกทริป)

|---|---|---|
| 1. Scheduled (มีคู่ตอบรับ ทริปยังไม่เริ่ม) | แผนที่: ตนเอง + จุดรับ (ถ้าตกลงแล้ว) ไม่มีตำแหน่งสดของคู่ สถานะ "ออกเดินทาง 18:00" Collapsed: แถบสถานะรอ (ไอคอนนาฬิกา + "รอออกเดินทาง" ไม่ใช่แถบสไลด์) ถ้าทริปตนยังไม่ "กำลังเดินทาง" ให้ใช้แถบสไลด์ "สไลด์เพื่อเริ่มออกเดินทาง" (ดู P-5) Half: จุดรับ/ชิปแชท/นัดจุดรับ | แผนที่เหมือนซ้าย Collapsed: แถบสไลด์ "สไลด์เพื่อเริ่มออกเดินทาง" (ปุ่มจับสีอำพัน) ถ้าเงื่อนไขเริ่มยังไม่ผ่าน (สถานะเดิม) แถบปิดใช้พร้อมเหตุผลใต้แถบ Half: จุดรับ/ชิปแชท/นำทางไปจุดรับ (ถ้าตกลงแล้ว) |

- ระหว่างสถานะเดียวกันไม่แสดงปุ่มที่ไม่เกี่ยวข้อง (เหตุผล: ลดความสับสน) ไม่ใช้การซ่อนด้วยสีจาง

#### F.3.5 Arrived: รายละเอียดข้อความ
- หัวข้อ: ใช้ตามตาราง F.8 (ถึงบ้านปลอดภัย / ถึงที่หมายแล้ว ตามเงื่อนไข Q5)
- ไม่แสดงตัวเลขระยะ/พิกัด; แผนที่ยังแสดงเส้นทางที่ผ่านมาโดยจาง 40% (ตามเดิม) ไม่มีตำแหน่งสดใด ๆ

## F.4 SwipeToConfirmSlider

### F-4 SwipeToConfirmSlider
- Purpose: ยืนยันการเปลี่ยนสถานะปกติ 3 อย่างเท่านั้น: เริ่มทริป, ขึ้นรถแล้ว, ถึงแล้ว; ห้ามใช้กับ SOS/ยกเลิก/รายงาน/ลบ (ใช้ dialog เดิม)
- Props เชิงเนื้อหา (ไม่ใช่โค้ด): label ข้อความ, การกระทำ (start/board/arrive), สถานะเงื่อนไข (enabled/disabled + เหตุผล), โหมดใกล้ถึง (on/off)

#### F.4.1 ขนาดและโครงสร้าง
- ความกว้าง: เต็มความกว้างของ sheet ลบ padding 16 ทั้งสองข้าง (บนจอ 390 dp = 358 dp; ต่ำสุด 288 dp)
- ความสูงราง: 64 dp (ค่าต่ำสุด 56 dp ตาม 1.3); ที่ text scale > 130% ความสูงราง = สูงตามข้อความ (ไม่ตัดข้อความ) สูงสุด 96 dp แล้วข้อความขึ้น 2-3 บรรทัด; thumb คงที่ 56x56 dp วงกลม ไม่ขยายตามตัวอักษร
- ราง: pill radius 32, ขอบ 1.5 dp (2 dp ในโหมดใกล้ถึง); ระยะขอบใน 4 dp (thumb ห่างขอบราง 4 dp)
- Thumb: วงกลม 56 dp เริ่มด้านซ้าย ไอคอน chevron ซ้อนสองชั้น (>>) 24 dp; พื้นที่แตะ thumb = 56x56 ขยายถึง 64x64 ในแนวตั้ง (เต็มความสูงราง)
- ปลายทางด้านขวา: ไอคอนเครื่องหมายถูก 24 dp วงกลมเส้นประ (บอกจุดจบ) ห่างขอบ 20 dp
- ข้อความ: กลางราง, Label 14 -> ใช้ Body L 16 น้ำหนัก 600; พื้นที่ข้อความอยู่ระหว่างขอบขวาของ thumb (เมื่ออยู่ซ้ายสุด) ถึงไอคอนปลายทาง ห้ามข้อความทับ thumb: padding ซ้าย 72 dp ขวา 56 dp; ข้อความห่อบรรทัดได้
- Label ตามการกระทำ: "สไลด์เพื่อเริ่มออกเดินทาง" / "สไลด์เพื่อขึ้นรถแล้ว" / "สไลด์เมื่อถึงบ้านปลอดภัย" (ตัวสุดท้ายใช้ "สไลด์เมื่อถึงที่หมาย" เมื่อไม่ใช่บ้าน ดู P-4)

#### F.4.2 พฤติกรรมการลาก
- เริ่มลากได้เฉพาะที่ thumb (หรือรางส่วนที่ thumb อยู่) เมื่อนิ้วแตะ thumb: thumb ขยาย 1.06 เท่า (ถ้าไม่ reduce motion) + haptic เบา (light impact)
- ระหว่างลาก: thumb ตามนิ้วแนวนอน; ส่วน fill ตามหลัง thumb; ข้อความจางลงตามระยะ (opacity 100% -> 0% ที่ 60% ของทาง) เพื่อไม่ให้ทับ fill; ไม่ต้องลากตรง: ยอมให้เบี่ยงแนวตั้ง 48 dp
- ถึงจุดยืนยัน = thumb ถึง >= 95% ของระยะราง: haptic ยืนยัน (medium impact) ล็อก thumb ที่ปลาย
- ปล่อยก่อนถึง: thumb เด้งกลับซ้าย 200 ms ease-out (reduce motion: กลับทันที) ไม่เรียกอะไร ไม่มีข้อความ
- แตะเฉย ๆ บนราง/thumb: ไม่ทำงาน; แสดงคำใบ้ 3 วินาทีใต้แถบ "สไลด์ไปทางขวา หรือกดค้างที่แถบ 1.5 วินาที" (ปรากฏเป็นข้อความ ไม่ใช่แค่แอนิเมชัน; thumb ขยับเป็นใบ้ 12 dp เฉพาะเมื่อไม่ reduce motion)
- ขัดจังหวะ: ถ้าแอปเข้า background/หมุนจอ/เกิด incoming gesture ของระบบระหว่างลาก ให้ยกเลิกการลากและ thumb กลับซ้าย (ไม่ยืนยัน)

#### F.4.3 สถานะ
| สถานะ | รูปร่าง | ข้อความ/เสียงอ่าน |
|---|---|---|
| idle | ราง+thumb ซ้าย ตาม token | label การกระทำ |
| pressed | thumb ขยายเล็กน้อย + ขอบหนา 2 dp | (ไม่เปลี่ยน) |
| dragging | fill ตามนิ้ว ข้อความจาง | ค่าเปอร์เซ็นต์ไม่อ่านต่อเนื่อง (ไม่ประกาศระหว่างลาก) |
| long-pressing | fill/วงแหวนความคืบหน้าเต็มใน 1.5 วินาที ข้อความ "กดค้างไว้..." | ประกาศ "กดค้างเพื่อยืนยัน" ครั้งเดียว |
| submitting | thumb ล็อกที่ปลาย มี spinner แทนลูกศร ข้อความ "กำลังบันทึก..." ลากซ้ำไม่ได้ (ไม่มีการเรียกซ้ำ) | ประกาศ "กำลังบันทึก" |
| success | thumb เป็นเครื่องหมายถูก fill เต็มราง ข้อความเรียบร้อย (ตัวอย่าง "ขึ้นรถเรียบร้อยแล้ว") ค้าง 600 ms แล้วหน้าเปลี่ยนสถานะ | ประกาศข้อความสำเร็จ (polite) |
| error | แถบกลับ idle; ข้อความ error ไทยเหนือแถบ (ไอคอนเตือน + ข้อความ role=alert) พร้อม haptic แบบ error | ประกาศข้อความ error ทันที (assertive) |
| disabled | ราง = พื้นเดียวกับ idle แต่ขอบประ, thumb เทา (driver.text-disabled / rider text-secondary 60%), ไอคอนล็อกแทนลูกศร; ต้องมีข้อความเหตุผลใต้แถบ (เช่น "ขึ้นรถได้เมื่อทริปของคู่กำลังเดินทาง") | อ่านเป็น "ปิดใช้งาน <เหตุผล>" |
| offline | เหมือน idle; เมื่อยืนยันแล้วส่งไม่ได้ -> error "ยังบันทึกไม่ได้ เพราะไม่มีอินเทอร์เน็ต ยังไม่ถือว่าจบทริป" | ตามข้างบน |
| near (geofence) | ดู F.4.7 | ดู F.4.7 |

#### F.4.4 Haptics (เคารพการตั้งค่า haptic ของระบบ)
- แตะ thumb: light impact; ถึงจุดยืนยัน: medium impact; success: success notification; error: error notification; ยกเลิกเด้งกลับ: ไม่มี haptic; เริ่มกดค้าง: light, ครบ 1.5 วินาที: medium; ปิด haptic ในระบบ = ไม่สั่น (ข้อมูลยังสื่อด้วยข้อความ/ภาพ)

#### F.4.5 แอนิเมชันสำเร็จ
- ปกติ: fill เต็มรางใน 150 ms -> thumb แปลงเป็นวงกลมสำเร็จ (สี success ของโทน) + เครื่องหมายถูกวาดเส้น 200 ms -> ข้อความสลับ (cross-fade 150 ms) -> ค้าง 600 ms -> sheet สลับสถานะ (cross-fade 200 ms) เวลารวม <= 1.2 วินาที
- Reduce motion: ข้ามทุกการเคลื่อนไหว แสดงสถานะ success ทันที (เครื่องหมายถูกนิ่ง + ข้อความ) ค้าง 600 ms แล้วสลับสถานะทันที; ไม่ใช้ shimmer/pulse; การสื่อความสำเร็จต้องมาจากข้อความ+ไอคอน ไม่ใช่การเคลื่อนไหว

#### F.4.6 ทางเลือกที่เข้าถึงได้ (จำเป็น)
- กดค้าง (long-press) 1.5 วินาที ที่ราง (ทุกจุดบนราง) หรือ thumb: มีตัวบอกความคืบหน้า (วงแหวนรอบ thumb เส้น 3 dp หรือ fill เดินหน้าช้าเป็นเส้นตรง) ปล่อยก่อนครบ = ยกเลิก (ไม่ส่ง, ไม่ error); ครบ 1.5 วินาที = ผลเหมือนสไลด์ครบ (haptic + submitting + success)
- ยอมรับนิ้วขยับเล็กน้อยระหว่างกดค้าง (tolerance 24 dp) สำหรับผู้ที่มือสั่น
- Semantics: บทบาทปุ่ม, label = การกระทำ (เช่น "ขึ้นรถแล้ว"), hint = "ดับเบิลแตะเพื่อยืนยัน หรือกดค้างแล้วปล่อยเมื่อครบ" (ข้อความเฉพาะ hint), value = "พร้อมยืนยัน" / "ปิดใช้งาน <เหตุผล>" / "ใกล้ถึงแล้ว"; custom action ในเมนู actions ชื่อ "ยืนยัน: <การกระทำ>" ตรงกับการสไลด์ครบ
- Screen reader activate (ดับเบิลแตะ) = เรียก custom action เดียวกัน (ผู้ใช้ต้อง focus แล้วดับเบิลแตะ = เจตนาชัดเจน) ดู P-6
- Switch Access/แป้นพิมพ์ภายนอก: Enter/Space = custom action; Focus ring 3 dp ขอบราง (rider.primary / driver.amber-ink)
- ลำดับ focus: label ของสถานะ -> แถบสไลด์ (หนึ่ง focus stop) ข้ามการแยก thumb/ราง
- ข้อความช่วยเหลือแบบมองเห็น: ที่ Half/Full ใต้แถบมีข้อความ Caption "ลากไม่ได้? กดค้างที่แถบ 1.5 วินาที" (Collapsed ซ่อนเพื่อประหยัดพื้นที่ แต่แตะเฉย ๆ แสดงคำใบ้ตาม F.4.2)

#### F.4.7 ไฮไลต์เมื่อใกล้จุดหมาย (geofence < 150 ม.) — เพื่อการนำเสนอเท่านั้น
- ตัวเทียบ: แถบ "ขึ้นรถแล้ว" เทียบกับจุดรับที่ตกลงแล้ว; แถบ "ถึงแล้ว" เทียบกับปลายทางของผู้ใช้เอง; แถบ "เริ่มออกเดินทาง" ไม่มีไฮไลต์ (ไม่ใช้ geofence)
- เงื่อนไขแสดง: ระยะ < 150 ม. -> เข้าโหมด near; ระยะ >= 150 ม. (รวม = 150 ม. พอดี) ที่ไม่เคยเข้าโหมด near ไม่ไฮไลต์; การออกจากโหมด near ใช้ hysteresis (ข้อเสนอค่าให้ dev: ออกเมื่อ >= 180 ม. หรือคงอย่างน้อย 3 วินาที) ตามข้อกำหนด US-32 เพื่อไม่ให้กระพริบ; ไม่มีสิทธิ์ตำแหน่ง/ไม่มีสัญญาณ/ตำแหน่งไม่แม่น = ไม่ไฮไลต์ ไม่มีข้อความ error
- การนำเสนอ: (1) ราง+thumb เปลี่ยนเป็นสีเขียวตาม F.1 (crossfade 250 ms; reduce motion: สลับทันที) (2) ข้อความในรางเป็น 2 บรรทัด: บรรทัดบน Caption 12 ตัวหนา พร้อมไอคอนหมุดถูก "ใกล้ถึงแล้ว" (ใช้ "ใกล้จุดรับแล้ว" สำหรับแถบขึ้นรถ) บรรทัดล่างเป็น label การกระทำเดิม (3) semantics: value = "ใกล้ถึงแล้ว" และประกาศ polite ครั้งเดียวต่อการเข้าโหมด (ไม่ประกาศซ้ำภายใน 60 วินาที) (4) ไม่มีวงกลม 150 ม. บนแผนที่ (เก็บแผนที่ให้สะอาด)
- ไม่ทำให้: เปลี่ยนสถานะเอง, เปิด/ปิดแถบ, เปลี่ยนเกณฑ์ลากไกลขึ้น/สั้นลง; ผู้ใช้สไลด์ได้ทุกเมื่อแม้นอกรัศมี (ไม่มีข้อความเตือนว่า "ยังไม่ถึง")
- ตัวเลขระยะไม่แสดงบนหน้าจอ (ไม่แสดง "อีก 120 ม." เพื่อไม่ให้ดูเหมือนตรวจสอบสถานะ)

### F-6 ArrivedAtPickupButton ("ถึงจุดรับแล้ว", US-33; Driver เท่านั้น)

## F.5 CommuteCardDeck

### F-8 CommuteCard (การ์ดใบใหญ่)
- Layout: ความกว้าง = หน้าจอ - 32; สูงยืดหยุ่นตามเนื้อหา (ไม่ fix) สูงสุดไม่เกินพื้นที่ที่เหลือ ถ้าเนื้อหายาวกว่า (text scale ใหญ่) การ์ดเลื่อนแนวตั้งภายใน; radius 24; พื้น surface (Rider: rider.surface ขอบ rider.border / Driver: driver.surface ขอบ driver.border) เงากลาง
- ลำดับเนื้อหา (ตำแหน่งบนลงล่าง ห่าง 12 dp):
  1. Avatar L 96 dp แบบตัวอักษรย่อ (E-1 placeholder ข้ามสระนำหน้า; ไม่มีรูปจริงเด็ดขาดในผลค้นหา ตาม US-22) + ชื่อเล่น Title L 22 (ตัดบรรทัดได้ 2 บรรทัด) + RoleBadge C-32 (ไอคอน + คำ "คนขับ"/"คนนั่ง")
  2. แถวป้าย: VerifiedBadge C-3 (ป้ายยืนยัน/สถาบัน/บริษัท ตามสิทธิ์เปิดเผยเดิม เช่น "นิสิตจุฬาฯ"; ผู้ใช้ทั่วไปแสดง "บุคคลทั่วไป" ป้ายกลาง ไม่ใช้เป็นข้อความเตือน)
  3. บรรทัดความเข้ากัน: ไอคอนเส้นทาง + "ทางเดียวกัน ~N%" + ไอคอนนาฬิกา + "ออกเดินทาง 18:00" (ไม่มีแถบคะแนน ไม่มีดาว/หัวใจ เพื่อเลี่ยงภาษา dating)
  4. บล็อกบทบาท:
     - การ์ด Driver: ไอคอนรถ + ข้อความหนึ่งบรรทัดตัวหนา "รับได้ 1 คน · ไม่เกิน X จากปลายทางของเขา" (X รูปแบบตาม US-21: < 1,000 ม. เป็น "N ม." ปัดร้อย, >= 1,000 เป็น "N.N กม."); มี Caption ต่อ "คนขับรับส่งได้ไม่เกิน X จากปลายทางของเขา" ที่หน้า S-14 (ข้อความยาวตาม US-21); ไม่แสดงรุ่น/ทะเบียนรถ
     - การ์ด Rider: ไอคอนคน + "คนนั่ง" (ไม่มีข้อความเพิ่มเกิน requirement)
  5. คะแนน (ถ้า >= 3 รีวิวที่เปิดเผยแล้วและ `review.show_in_search` เปิด): ไอคอนดาว + "4.8 (12 รีวิว) ในฐานะคนขับ/คนนั่ง"; ไม่ถึงเกณฑ์ = ไม่แสดงบล็อกนี้ทั้งบล็อกและ layout ไหลต่อ ไม่มีช่องว่าง/ข้อความแทน
  6. Caption ความเป็นส่วนตัว (ไอคอนกุญแจ): "จะเห็นรูปและปลายทางจริงเมื่อจับคู่กันแล้ว" เพื่ออธิบายว่าทำไมไม่มีรูป
  7. ลิงก์ "ดูรายละเอียด" (เปิด S-14; พื้นที่แตะ 48 dp)
- ข้อมูลความปลอดภัย (ป้าย, บทบาท, ระยะรับส่ง) อยู่ในตำแหน่งคงที่ ไม่ถูกซ่อนด้วยการโต้ตอบ/ไม่ถูก stamp บัง (stamp วางที่มุมบน ห่างบล็อก 2-4)
- ไม่แสดง: รูปจริง, พิกัด, ปลายทางจริง, ระยะปลายทางจริงระหว่างสองทริป, ตัวตนนอกสิทธิ์
- Semantics: การ์ดเป็นกลุ่มเดียวที่อ่านต่อเนื่อง: "<ชื่อ>, <บทบาท>, <ป้าย>, ทางเดียวกันประมาณ N เปอร์เซ็นต์, ออกเดินทาง 18:00, <ข้อความบทบาท/ระยะ>, <คะแนนถ้ามี>. ปุ่ม: ข้าม, ชวนกลับด้วยกัน, ดูรายละเอียด" (Avatar ตั้ง excludeSemantics)
- States: default / dragging-right / dragging-left / exiting / entering-back (undo) / skeleton (loading) / unavailable (ดู F.5.5)

#### F.5.2 ท่าทางปัด (ทางเลือกของปุ่ม)
- ปัดขวา = ชวน; ปัดซ้าย = ข้าม; ขณะลาก การ์ดเคลื่อนตามนิ้ว หมุน (ไม่เกิน 8 องศา) และ stamp โผล่:
  - ขวา: Stamp "ชวน" (ไอคอนหัวใจ + ข้อความ) ที่มุมบนซ้ายของการ์ด, opacity ตามระยะ 0 -> 100% ที่ 30% ของความกว้าง; ขอบการ์ดเขียว (โทน success)
  - ซ้าย: Stamp "ข้าม" (ไอคอน ✕ + ข้อความ) ที่มุมบนขวา; ขอบการ์ดกลาง (border-strong)
  - Stamp มีไอคอนและข้อความเสมอ (ไม่พึ่งสี); reduce motion: ไม่หมุน ไม่เลื่อนตามนิ้วเป็นมุม แต่ยังต้องเห็น stamp เปลี่ยนตามทิศ
- สแนป: ปล่อยเมื่อเลื่อนเกิน 35% ของความกว้างการ์ด หรือความเร็ว > 700 dp/วินาที = ยืนยันทิศนั้น (การ์ดหลุดจอ 180 ms); ไม่ถึง = เด้งกลับ 200 ms
- ขั้นตอนความปลอดภัย: ขณะปัดไม่ให้เนื้อหาการ์ดถูกเลื่อนแนวตั้งพร้อมกัน (แยกแกนตามทิศเริ่มต้น)
- ท่าทางทั้งหมดเทียบเท่าปุ่ม; ผู้ใช้ไม่ต้องปัดเพื่อใช้ฟีเจอร์ใด

### F-9 DeckActionBar (ปุ่ม ✕ / 💚)
- Layout: แถวใต้พื้นที่การ์ด: [✕ ข้าม] [ดูรายละเอียด] [ชวนกลับด้วยกัน 💚]; ✕ ปุ่มวงกลม 64 dp (ไอคอนเวกเตอร์ ✕) มีข้อความ "ข้าม" ใต้ปุ่ม (Caption 12 หรือ Label 14 ตาม text scale); 💚 ปุ่ม 72 dp พื้นเขียวตาม F.1 ไอคอนหัวใจ + ข้อความ "ชวนกลับด้วยกัน"; ทั้งสองอยู่ในพื้นที่ที่ระยะห่างจากขอบล่าง >= 16 dp + safe area
- Semantics: "ข้าม" / "ชวนกลับด้วยกัน" (ไม่อ่านชื่อ emoji ซ้ำ); focus ได้ ลำดับ focus: การ์ด -> ข้าม -> ดูรายละเอียด -> ชวน
- States: default / pressed / disabled (💚 ปิดเมื่อเพดานเต็ม: แสดงเหตุผลใต้ปุ่ม "ตอนนี้ชวนได้พร้อมกันครบ <จำนวนเพดาน> คนแล้ว รอเพื่อนตอบก่อนนะ") / sending (💚 กำลังชวน; ปิดกดซ้ำ; การ์ดเดียวไม่ส่งซ้ำ) / hidden ในสถานะ empty/end
- ประกาศ: ✕ -> "ข้าม <ชื่อ> แล้ว การ์ดถัดไป ..." ; 💚 -> ตาม F-10

### F-10 UndoSnackbar (เลิกชวน 5 วินาที)
- Purpose: กันปัดขวา/กดพลาด
- ตำแหน่ง: ลอยเหนือ DeckActionBar (ไม่บังปุ่ม) ยึดด้วย snackbar host ระดับแอป (ไม่หายเมื่อเปลี่ยนหน้าภายใน 5 วินาที)
- เนื้อหา 2 เฟส (ดู P-3 ข้อเสนอ ถ้าเลือกส่งหน่วง): เฟส 1 "กำลังชวน <ชื่อ>..." + ปุ่ม "เลิกชวน" (ปุ่ม 48 dp) + แถบเวลาบางด้านล่าง 5 วินาที (reduce motion: แสดงข้อความ "เหลือ 5 วินาที" นิ่ง ไม่วิ่ง) -> เฟส 2 หลังส่งสำเร็จ "ชวนเพื่อนแล้ว! รอเพื่อนตอบแป๊บนะ" (ไม่มี undo แล้ว; มีลิงก์ "ดูคำขอ") ค้าง 4 วินาที
- Snackbar ไม่หายขณะ screen reader/แป้นพิมพ์ focus อยู่ที่ปุ่ม "เลิกชวน" (timer หยุดชั่วคราว; ต่อเมื่อ focus ออก + 5 วินาทีขั้นต่ำเมื่อเปิด TalkBack/VoiceOver ปรับเป็น 8 วินาที: ข้อเสนอ P-3)
- ประกาศ: ทันทีที่โผล่ (polite) "กำลังชวน <ชื่อ> กดเลิกชวนได้ภายใน 5 วินาที"
- ปัดขวารัว ๆ: คำขอก่อนหน้าที่ยังอยู่ในกรอบ undo ถูกยืนยันส่งทันที และ snackbar แสดงเฉพาะคำขอล่าสุด (undo ได้เฉพาะใบล่าสุด); ต่อ 1 การ์ด = 1 คำขอ
- ผิดพลาด: ข้อความไทย (ตาม F.5.5) + การ์ดกลับมา/ข้ามอย่างสุภาพ
- Race: undo หลังอีกฝ่ายตอบรับแล้ว (ถ้าเลือกส่งทันที): ข้อความ "เพื่อนตอบรับไปแล้ว ยกเลิกไม่ได้นะ" -> เปิด Match Moment

## F.6 Match Moment

### F-13 MatchMomentModal
- Purpose: ฉลองการจับคู่สำเร็จและพาไปขั้นต่อไปทันที
- รูปแบบ: โมดอลกลางจอ (dialog) ทับหน้าปัจจุบัน; scrim ตามโทน (Rider: navy 50%; Driver: driver.scrim 60%); การ์ดกว้างสูงสุด 360 dp, radius 24, พื้น surface (Rider) / surface-raised (Driver); ไม่ใช่ route (ไม่มี URL)
- เนื้อหา:
  1. ปุ่มปิด X มุมขวาบน 48 dp (label "ปิด")
  2. ภาพ: Avatar L 96 สองวงซ้อนกันเล็กน้อย: ตนเอง + คู่; รูปจริงแสดงได้เพราะจับคู่ตอบรับแล้ว (US-22/สมมติฐาน 14) ถ้าไม่มีรูปใช้ตัวอักษรย่อ; ตรงกลางระหว่างวงมีไอคอนเชื่อมสีเขียว (ตามโทน)
  3. เอฟเฟกต์ฉลอง: ชิ้นกระดาษสี (confetti) 1.5 วินาทีพื้นหลังการ์ด (decorative; reduce motion = ไม่มี confetti แสดงไอคอนปาร์ตี้นิ่งแทน)
  4. หัวข้อ Title L "ได้เพื่อนกลับบ้านแล้ว! 🎉" (🎉 ห่อด้วยข้อความทางเลือก: อ่านเป็น "ฉลอง" หรือถูกข้ามเพราะข้อความหลักอ่านครบ; ดู F.8)
  5. บรรทัดรอง: "<ชื่อเล่นคู่> ไปด้วยกันกับคุณ" (ไม่แสดงปลายทางของอีกฝ่าย)
  6. ปุ่มหลัก "ทักทายนัดจุดรับ" (56 dp เต็มความกว้าง) -> เปิดแชทพร้อมข้อความทักทายในช่องพิมพ์ (ข้อความตัวอย่าง "สวัสดี! เรานัดจุดรับกันที่ไหนดี" ไม่แนบพิกัด/ชื่อสถานที่ ไม่ส่งอัตโนมัติ)
  7. ปุ่มรอง "ดูแผนที่การเดินทาง" (ปุ่มขอบ 56 dp)
  8. ข้อความความปลอดภัยที่ต้องแสดงตามกฎเดิม (ถ้ามี เช่น เตือนนัดในที่สาธารณะ ข้อความเดิม) แสดงใต้ปุ่มเป็น Caption ไม่ถูกซ่อน
- ปิดโมดอล: X / แตะ scrim / back = ปิดโดยไม่เสียการจับคู่; ทุกทางปิดตั้ง flag "เห็นแล้ว" ต่อ match (เก็บในเครื่อง)
- Focus/SR: เมื่อเปิด focus ไปที่หัวข้อ, ประกาศ "ได้เพื่อนกลับบ้านแล้ว"; focus ติดในโมดอล (trap) ลำดับ: หัวข้อ -> ทักทายนัดจุดรับ -> ดูแผนที่ -> ปิด; เมื่อปิด focus กลับองค์ประกอบเดิมก่อนโมดอล
- ถ้ามีหลายการจับคู่พร้อมกัน: แสดงทีละโมดอล (คิว)
- States: default / loading-peer (ข้อมูลคู่ยังโหลด: ตัวอักษรย่อ + skeleton ชื่อ ไม่เกิน 3 วินาที) / error (ไม่แสดงโมดอล เข้าหน้า match เดิม) / match-cancelled (ไม่แสดง) / map-unavailable (ปุ่ม "ดูแผนที่การเดินทาง" -> /matches/:id + snackbar "ยังไม่ถึงเวลาเดินทาง ดูรายละเอียดการจับคู่ก่อนนะ")

  4. (เฉพาะขับรถเอง) แถวระยะรับส่ง: ไอคอนรถ + "รับส่งห่างจากปลายทางคุณได้ไม่เกิน 2 กม." + ปุ่มลิงก์ "ปรับ" (เปิด control เดียวกับ wizard ขั้น 2); ค่าเริ่มต้น 2,000 ม. จำค่าที่ใช้ล่าสุด แสดงให้เห็นก่อนสร้างเสมอ
  5. ปุ่มหลัก "หาเพื่อนกลับบ้าน" เต็มความกว้าง 56 dp (Rider: rider.primary / Driver: driver.amber)
  6. (เฉพาะไม่พร้อม) ข้อความช่วยใต้ปุ่ม + ลิงก์ "สร้างทริปเองทีละขั้น" (wizard)
- ตัวเลือก "ขับรถเอง" เมื่อยังไม่ลงทะเบียนคนขับ/ไม่มีข้อมูลรถ: segment ยังเห็นได้แต่ไม่เลือกให้โดยอัตโนมัติ; แตะแล้วแสดง inline "ต้องลงทะเบียนคนขับก่อน" + ลิงก์ "ลงทะเบียนคนขับ" (US-19) ไม่เด้ง dialog เอง
- States: ready / missing-preset (ดูด้านล่าง) / partial-preset (ตั้งบ้านแล้วแต่ยังไม่ตั้งจุดเริ่ม หรือกลับกัน: บอกว่าขาดอะไร + "ตั้งค่าต่อ") / creating (ปุ่ม loading "กำลังสร้างทริป..." ปุ่มปิด ไม่เลือกเวลา/บทบาทได้) / error-network ("สร้างทริปไม่สำเร็จ ลองอีกครั้งนะ" + ลองใหม่) / error-validation (ข้อความเหตุผลไทยจากกฎเดิม + "ไปตั้งทีละขั้น" พร้อมค่าที่กรอก) / driver-not-ready / has-active-trip (การ์ดหาย, แสดงแบนเนอร์) / offline (ปุ่มปิดใช้ + ข้อความ)
- Missing-preset: การ์ดหัวข้อ "ตั้งบ้านไว้ แล้วกลับบ้านได้ในแตะเดียว" + คำอธิบาย 1 บรรทัด "เก็บไว้ในเครื่องนี้เท่านั้น" + ปุ่มหลัก "ตั้งค่าสถานที่โปรด" + ปุ่มรอง "สร้างทริปเอง" (wizard)
- Semantics: การ์ดเป็น landmark "ทางลัดกลับบ้าน"; ชิปเวลาเป็นกลุ่ม radio; ปุ่มหลักอ่านเป็น "หาเพื่อนกลับบ้าน เวลา <เวลา> โหมด <บทบาท>"

### F-15 TimeChipRow
- ชิป 48 dp สูง (กว้างตามข้อความ, ระยะห่าง 8), เลื่อนแนวนอนได้เมื่อ text scale ใหญ่, single-select; ค่าเริ่มต้น = ค่าล่าสุดถ้ายังเป็นอนาคต ไม่งั้น "ตอนนี้เลย"
- ชิป: "ตอนนี้เลย" / "17:30" / "18:00" / "เวลาอื่น..." (เปิด DepartureTimeSelector C-9)
- เวลาที่ผ่านแล้วในวันนี้ไม่แสดงเป็นอนาคต: ถ้า 17:30 หรือ 18:00 ผ่านแล้ว แทนด้วยช่วงครึ่งชั่วโมงถัดไปที่ยังไม่ผ่าน (ให้เหลืออย่างน้อย 3 ตัวเลือกที่เลือกได้) -- ข้อเสนอต่อ Q8
- สถานะที่เลือก: พื้น primary-tint (Rider) / surface-raised + ขอบ amber (Driver) + ไอคอนถูก (ไม่พึ่งสีอย่างเดียว)
- Semantics: "ตอนนี้เลย, เลือกแล้ว" / "17:30 น."

### F-16 PresetSetupFlow (สถานที่โปรด)
- เข้าจาก: การ์ดหน้าแรก (missing/partial) และ /me > "สถานที่โปรด" (แถวใหม่ใน S-27)

#### P-1 แผ่นแจ้งความเป็นส่วนตัว (ก่อนบันทึกครั้งแรกเท่านั้น)
- หัวข้อ "เก็บไว้ในเครื่องนี้เท่านั้น"
- เนื้อหา (ไอคอนกุญแจ): "บ้านและจุดเริ่มประจำของคุณเก็บไว้ในเครื่องนี้เท่านั้น ไม่ถูกส่งไปที่เซิร์ฟเวอร์ ไม่ตามไปเมื่อเปลี่ยนเครื่อง (ต้องตั้งใหม่) และจะถูกลบเมื่อออกจากระบบหรือลบบัญชี คุณลบเองได้ทุกเมื่อ" + บรรทัดสำคัญ: "เมื่อสร้างทริป จุดเริ่มและปลายทางของทริปนั้นจะถูกบันทึกตามปกติ" (ตรงกับ US-38 ข้อสุดท้าย เพื่อไม่ให้เข้าใจผิดว่าไม่มีการเก็บเลย)
- ปุ่ม "เข้าใจแล้ว ไปต่อ" (หลัก) / "ยกเลิก"
- บันทึกว่าผู้ใช้เห็นแล้วในเครื่อง (ต่อบัญชี)

#### P-2 ขั้น "บ้าน" (/me/places/home)
- ช่องชื่อ (ค่าเริ่มต้น "บ้าน" แก้ได้ <= 20 ตัวอักษร) + PlaceSearchField C-8 + แผนที่ปักหมุด (AppMap C-6) + ปุ่ม "ใช้ตำแหน่งปัจจุบัน" (ขอสิทธิ์ตามเดิมพร้อม PermissionRationale)
- ปุ่ม "ต่อไป" ปิดใช้จนเลือกสถานที่

#### P-3 ขั้น "จุดเริ่มประจำ" (/me/places/start)
- เลือกประเภทด้วยชิป: "ที่ทำงาน" / "มหาวิทยาลัย" / "อื่นๆ" (อื่นๆ = พิมพ์ชื่อเอง) ; ค้นหา/ปักหมุดเหมือนบ้าน
- ตรวจ: ถ้าจุดเริ่มเท่ากับ/ใกล้บ้านเกินกฎ validation เดิม: ข้อความใต้ช่อง "จุดเริ่มกับบ้านอยู่ที่เดียวกัน ลองเลือกจุดเริ่มใหม่" และไปต่อไม่ได้

#### P-4 สรุป (/me/places)
- 2 แถว SettingsTile C-28: "บ้าน: <ชื่อ>" และ "จุดเริ่มประจำ: <ชื่อ>" แต่ละแถวมีปุ่ม "แก้ไข" และ "ลบ" (>= 48 dp) + caption "เก็บไว้ในเครื่องนี้เท่านั้น" + ปุ่ม "เสร็จ"
- ลบ: ConfirmDialog (C-23) "ลบ <ชื่อ> ออกจากเครื่องนี้?" ปุ่ม "ลบ" (danger) / "ยกเลิก" (ยังใช้ dialog ตามข้อกำหนด ไม่ใช้สไลเดอร์); ลบจริงแล้ว snackbar "ลบแล้ว"
- บันทึกสำเร็จ: snackbar "บันทึกไว้ในเครื่องนี้แล้ว"
- States: empty (ยังไม่ตั้ง: ภาพไอคอนบ้าน + ข้อความ + ปุ่ม "ตั้งบ้าน") / partial / complete / saving / error-storage ("บันทึกไม่สำเร็จ ลองอีกครั้งนะ") / searching (C-8 states)
- เมื่อออกจากระบบ/ลบบัญชี: ข้อมูลถูกล้าง (ไม่มี UI ต้องแสดง); สลับบัญชีเห็นเฉพาะของตน

### F.8.3 กติกา emoji
- ห้ามใช้ emoji เป็นสื่อความอย่างเดียว; ทุก emoji ในประโยคต้องมีข้อความครบความหมายอยู่แล้ว; ตั้ง semantics ให้ label ของ Text ทั้งประโยคเป็นข้อความที่ไม่มีชื่อ emoji (หรือให้ emoji เป็นส่วนตกแต่งที่ถูกข้าม)
- ข้อความ error/ความปลอดภัย/ความเป็นส่วนตัว/ยินยอม/SOS/ยกเลิก/ลบ ห้ามมี emoji และห้ามเปลี่ยนเป็นโทนสัพยอก
- ตัวเลขและปุ่ม ✕ / 💚: ปุ่มใช้ไอคอนเวกเตอร์ + ข้อความ ไม่ใช้ emoji ในปุ่ม (เพื่อเรนเดอร์สีสม่ำเสมอบนทุกอุปกรณ์และ contrast ผ่าน)

- sheet: ที่จับเป็นปุ่มพร้อม action ขยาย/ย่อ; ประกาศ "แผ่นข้อมูลขยายเป็นเต็มจอ" เมื่อเปลี่ยนระดับ; focus ไม่กระโดดออกจากตำแหน่งเมื่อเปลี่ยนระดับ; เนื้อหาที่ถูกซ่อนเมื่อ Collapsed ต้องไม่อยู่ใน focus order
- แถบสไลด์: ตาม F.4.6 (กดค้าง, custom action, ดับเบิลแตะ); ข้อความ error ประกาศทันที; success ประกาศ; ไม่ประกาศระหว่างลาก
- Geofence: ไม่พึ่งสี (ข้อความ + ไอคอน + semantics "ใกล้ถึงแล้ว")
- Deck: ทุกการปัดมีปุ่ม; การ์ดอ่านต่อเนื่องเป็นประโยคเดียว; snackbar undo ประกาศและหยุด timer เมื่อ focus; หลังข้ามหรือชวน focus ไปการ์ดใบถัดไป (หัวข้อชื่อ) ไม่ตกไปที่ตัวการ์ดที่หายไป; ประกาศตัวนับ "2 จาก 7"
- Match Moment: focus trap, ประกาศหัวข้อ, ปิดด้วย back/Escape, คืน focus
- การ์ดหน้าแรก: ชิปเวลา/บทบาทเป็นกลุ่ม radio; สถานะ loading ประกาศ; error เชื่อมกับปุ่มด้วย description
- Contrast: ตามตาราง F.1 และ D.1.3; ขนาดแตะ >= 48 dp (สไลด์ 56/64, SOS >= 56, ปุ่มหลักในทริป >= 56)
- Text scale 200%: การ์ด deck เลื่อนภายในได้; แถบสไลด์ยืดสูง; ชิปเวลาเลื่อนแนวนอนหรือขึ้นบรรทัดใหม่; RideTopOverlay ยุบปุ่ม pill เป็นไอคอน; ไม่มีสิ่งใดตัดข้อความสำคัญหรือบัง SOS
- Reduce motion: ไม่เลื่อน sheet แบบสปริง (ใช้สแนปด้วย fade/ตำแหน่งทันที), ไม่มี confetti, ไม่หมุนการ์ด, ไม่มี shimmer/pulse, thumb กลับ/ย้ายทันที, สถานะสื่อด้วยข้อความ+ไอคอน
- Haptics: เคารพการตั้งค่าระบบ; ไม่ใช้ haptic เป็นช่องทางเดียวในการสื่อ
- อุปกรณ์เสริม: Switch Access/keyboard ใช้ custom action ของสไลด์และปุ่ม ✕/💚 ได้

## F.13 States รวม (checklist ต่อ component)
- ทุก component มี loading/empty/error ที่ระบุไว้ใน section ของตน; ข้อความไทยทุกข้อ; ไม่มีสถานะค้างโดยไม่มีทางออก (ลองใหม่/ย้อนกลับ)

## ข้อเสนอแนะที่อาจขัดกับ requirement / ต้องให้ PM ตัดสิน (รอบ 6)

### P-1 รูปโปรไฟล์บนการ์ด (ร่างของผู้ใช้ขัดกับ US-22)
- ประเด็น: ร่างเดิมต้องการรูปโปรไฟล์บนการ์ด แต่ US-22 ห้ามเห็นรูปในผลค้นหาก่อนจับคู่; BA/orchestrator ตัดสินใจใช้ตัวอักษรย่อ (สมมติฐาน 15, Q3)
- ทางเลือก A (แนะนำ; ใช้ใน spec นี้): ตัวอักษรย่อ + ชื่อเล่น จนกว่าจับคู่ตอบรับแล้ว (รูปจริงเห็นใน Match Moment และหน้าจับคู่); การ์ดใช้ caption อธิบายเหตุผล ไม่ต้องแก้กฎรูป
- ทางเลือก B: ให้เจ้าของรูปเลือกเปิดรูปในผลค้นหาแบบ opt-in (ต้องผ่านฝ่ายกฎหมาย/PDPA และแก้ RLS/`find_matches` ซึ่งขัดกับ scope รอบนี้ และเสี่ยงการตัดสินจากหน้าตา ขัดสมมติฐาน 3)

### P-2 "รับได้ 1 คน" กับถ้อยคำระยะรับส่ง
- ประเด็น: ร่างของผู้ใช้ใช้ "รับได้ 1 คน · ไม่เกิน X จากปลายทางของเขา" แต่ US-21/US-34 ใช้ "คนขับรับส่งได้ไม่เกิน X จากปลายทางของเขา"
- ทางเลือก A (แนะนำ; ใช้ใน spec นี้): ที่การ์ดใช้รูปย่อของผู้ใช้ ที่หน้า S-14 ใช้ข้อความยาวตาม US-21
- ทางเลือก B: ใช้ข้อความยาวทั้งสองที่ (การ์ดจะสูงขึ้น 1 บรรทัดที่ text scale ใหญ่)

### P-3 Undo 5 วินาที: ส่งทันทีแล้วยกเลิก vs หน่วงส่ง (ชนกับ US-40 และ Q6)
- ประเด็น: US-35 ต้องการให้ผู้รับไม่เห็นคำขอที่ถูก undo ทัน (สื่อว่าควรหน่วงส่ง) แต่ US-40 ให้ข้อความ "ชวนเพื่อนแล้ว" แสดงเฉพาะหลังส่งสำเร็จ; ถ้าหน่วงส่ง ข้อความ "ชวนเพื่อนแล้ว" ต้องเลื่อนไปหลังหมดเวลา; และต้องตัดสินว่าคำขอที่ถูก undo นับเพดาน/throttle หรือไม่ (Q6)
- ทางเลือก A (แนะนำ; ใช้ใน spec นี้): หน่วงส่ง 5 วินาที; เฟส 1 แสดง "กำลังชวน <ชื่อ>..." + เลิกชวน; เฟส 2 หลังส่งสำเร็จแสดง "ชวนเพื่อนแล้ว! รอเพื่อนตอบแป๊บนะ"; undo ไม่นับเพดาน/throttle; ข้อเสีย: ถ้าปิดแอปภายใน 5 วินาที คำขออาจไม่ถูกส่ง (แจ้งผู้ใช้ผ่านสถานะ "ยังไม่ได้ส่ง"?) ควรยืนยัน flush ตอนปิดแอป
- ทางเลือก B: ส่งทันที + undo = ยกเลิกคำขอ; snackbar "ชวนเพื่อนแล้ว! ..." ทันทีหลังสำเร็จ พร้อม "เลิกชวน"; ข้อเสีย: ผู้รับเห็น/ได้รับแจ้งก่อนแล้วค่อยหาย, นับเพดาน/throttle, เสี่ยงแข่งกับการตอบรับ
- นอกจากนี้: ข้อเสนอให้ snackbar ค้างนานขึ้นเป็น >= 8 วินาทีเมื่อเปิด screen reader (ช่วงเวลา 5 วินาทีสั้นเกินสำหรับผู้ใช้ TalkBack/VoiceOver) โดยยังเรียก "ประมาณ 5 วินาที" สำหรับผู้ใช้ทั่วไป

### P-4 คำว่า "ถึงบ้านปลอดภัย" กับทริปที่ปลายทางไม่ใช่บ้าน (Q5)
- ประเด็น: แถบสไลด์และหน้า Arrived ใช้ "ถึงบ้านปลอดภัย" แต่ไม่มีคอลัมน์ว่าปลายทางเป็นบ้าน และ preset เก็บในเครื่อง
- ทางเลือก A: ใช้ "ถึงบ้านปลอดภัย" ทุกทริป (เสี่ยงผิดความหมายกับทริป Peer/สถานที่อื่น)
- ทางเลือก B: ใช้ "ถึงที่หมาย" ทุกทริป (ปลอดภัย แต่ไม่ตรงร่างผู้ใช้)
- ทางเลือก C (แนะนำ): ใช้ "บ้าน" เมื่อทริปสร้างจากการ์ดกลับบ้านบนเครื่องนี้ หรือปลายทางของทริปตรงกับ preset บ้านในเครื่องภายในรัศมี (เปรียบเทียบบนเครื่อง ไม่ส่ง server) ที่เหลือใช้ข้อความทั่วไป "ถึงที่หมาย" (ต้องให้ PM ยืนยันถ้อยคำ และวิธีเปรียบเทียบ)

### P-5 สถานะ Scheduled และใครเริ่มทริปของ Rider
- ประเด็น: US-29 กล่าวถึงทริป "กำลังดำเนินอยู่" แต่ต้องการให้มีสถานะ scheduled/ก่อนเริ่ม และ US-31 ระบุเริ่มทริปสำหรับ Driver; ไม่ชัดว่า Rider ต้องเริ่มทริปของตนเองหรือไม่ (แต่ "ขึ้นรถแล้ว" ต้องเมื่อทริปทั้งสองกำลังเดินทาง)
- ทางเลือก A (ใช้ใน spec นี้): UnifiedRideScreen เปิดได้เมื่อมีทริปของตนที่ยังไม่จบ (รวมยังไม่เริ่ม) และมีคู่ตอบรับ; ผู้ที่ทริปตนยังไม่ "กำลังเดินทาง" ใช้แถบสไลด์ "สไลด์เพื่อเริ่มออกเดินทาง" เหมือนกัน (ทั้ง Rider และ Driver ตาม baseline ActiveTripScreen)
- ทางเลือก B: เปิด Unified เฉพาะเมื่อทริป "กำลังเดินทาง" ทั้งหมด; ก่อนหน้านั้นใช้หน้า /matches/:id เดิม (Match Moment "ดูแผนที่การเดินทาง" จะไปหน้า match เสมอจนถึงเวลาเดินทาง) — ตัดสถานะ Scheduled ออกจากหน้านี้

### P-6 Screen reader activate สไลด์ได้ทันทีโดยไม่มี confirm
- ประเด็น: US-31 ต้องการทางเลือกเข้าถึงได้ (semantics action) และไม่มี dialog; การดับเบิลแตะเป็นขั้นเดียว อาจกดพลาดได้มากกว่าการสไลด์
- ทางเลือก A (แนะนำ): custom action + ดับเบิลแตะ ยืนยันทันที (focus ก่อนแล้วจึงดับเบิลแตะ ถือว่าเจตนา) เพราะการกระทำอยู่ใน 3 อย่างที่ AC กำหนดให้ตัด dialog
- ทางเลือก B: ผู้ใช้ screen reader ต้องกดค้างเท่านั้น (ไม่มี activate ตรง) เพื่อเท่ากับผู้ใช้ปกติ; ข้อเสีย: กดค้างบางครั้งทำได้ยากกับ screen reader

### P-7 ตัวสลับบทบาทบนการ์ดหน้าแรก = active role ของแอป (เปลี่ยนโทนทั้งแอป)
- ประเด็น: D.0 กำหนดว่า active role = โทนระดับแอป + role เริ่มต้นของทริปใหม่; การสลับที่การ์ดจึงเปลี่ยนโทนทั้งแอป (ตามที่ผู้ใช้คาดว่าเป็น "ตัวสลับบทบาท")
- ทางเลือก A (ใช้ใน spec นี้): ตัวสลับบนการ์ด = active role เดียวกัน; เปลี่ยนโทนตาม D.6
- ทางเลือก B: ตัวสลับบนการ์ดเป็นค่าเฉพาะของทริปที่จะสร้าง ไม่เปลี่ยนโทนแอป (ข้อดี: ไม่เปลี่ยนสี; ข้อเสีย: บทบาทที่เห็นในแอปกับบทบาทของทริปที่จะสร้างต่างกัน สับสนตาม D.0)

### P-8 SOS ในสถานะ Scheduled ก่อนเริ่มทริป
- ประเด็น: US-30 ระบุ SOS "ขณะทริปกำลังเดินทาง"; ใน Scheduled (ยังไม่เริ่ม) ผู้ใช้อาจนัดพบคู่และต้องการ SOS
- ทางเลือก A (แนะนำ): แสดง SOS ลอยตั้งแต่ Scheduled ที่มีคู่ตอบรับ (ไม่มีข้อเสียเชิงความเป็นส่วนตัว)
- ทางเลือก B: ตาม requirement ตรง ๆ ไม่แสดงจนกว่าจะกำลังเดินทาง (ใช้ /sos ใน Safety)

### P-9 ปุ่ม "ถึงจุดรับแล้ว" แทนแถบสไลด์ใน Collapsed ของ Driver ก่อนรับ
- ประเด็น: US-29 กำหนดให้ Collapsed มี "แถบสไลด์หลัก" แต่ Driver ก่อนรับควรมีการกระทำหลักเป็น "ถึงจุดรับแล้ว" (US-33) ถ้าให้สไลด์ "ถึงแล้ว" อยู่ Collapsed พร้อมกัน เสี่ยงสไลด์พลาดจบทริปก่อนรับ
- ทางเลือก A (ใช้ใน spec นี้): Collapsed แสดงปุ่ม "ถึงจุดรับแล้ว" ก่อนรับ แล้วเปลี่ยนเป็นสไลด์ "ถึงแล้ว" หลัง Rider ขึ้นรถ; สไลด์ "ถึงแล้ว" ยังใช้ได้ทุกเมื่อจาก Half/Full
- ทางเลือก B: แสดงทั้งปุ่มและสไลด์ใน Collapsed (สูง Collapsed เพิ่ม ~56 dp)

### P-10 ตำแหน่ง SOS ที่ย้ายไปมุมขวาบน
- ประเด็น: E-8 รอบ 5 ระบุว่า SOS อยู่ "ตำแหน่งเดิมของหน้า active trip" (ล่างขวา) แต่ sheet 3 ระดับสูงถึง Full ทำให้ตำแหน่งล่างถูกบัง
- ทางเลือก A (ใช้ใน spec นี้): ย้ายเป็นชั้นลอยมุมขวาบน (ไม่ถูก sheet/แป้นพิมพ์บัง); ผู้ใช้ที่คุ้นตำแหน่งเดิมต้องเรียนรู้ใหม่ (ควรมี coach mark ครั้งเดียว)
- ทางเลือก B: ผูก SOS ให้เลื่อนตามขอบบนของ sheet (ตำแหน่งล่างขวาเหนือ sheet) แต่ใน Full ต้องซ้อนบน sheet ทำให้บังเนื้อหาและอาจชนแป้นพิมพ์

### P-11 ตัวเลือกเวลา 17:30/18:00 (Q8) และคะแนนบนการ์ด (Q7)
- ประเด็น: เวลาผ่านแล้วต้องไม่เสนอเป็นอนาคต; คะแนนบนการ์ดพึ่งการขยาย `find_matches`
- ทางเลือก A (แนะนำ): ชิปเวลาคงที่ + ตอนนี้เลย; เมื่อผ่านแล้วแทนด้วยครึ่งชั่วโมงถัดไป; การ์ด deck ออกแบบให้บล็อกคะแนนหายไปได้ทั้งบล็อก (layout ไม่พึ่ง) จึงส่งมอบ deck ก่อนได้ถ้า DB ไม่ทัน
- ทางเลือก B: คำนวณชิปจากเวลาปัจจุบัน/พฤติกรรมผู้ใช้ (ต้องเก็บพฤติกรรมเพิ่ม ขัดหลักไม่ทำโปรไฟล์)

### P-12 การ์ดจำนวนคนนั่งและ persona
- ประเด็น: ไม่มี (ที่นั่งคงที่ 1 ตามสมมติฐาน 8) -- แจ้งเพื่อทราบว่า "รับได้ 1 คน" แสดงเฉพาะการ์ด Driver
