# สถานะโปรเจกต์ "กลับด้วยกันมั้ย" — อัปเดตล่าสุด 2026-09-29

> ไฟล์นี้สรุปภาพรวมทั้งโปรเจกต์ ไว้ให้เรียกอ่านทีหลังโดยไม่ต้องไล่ประวัติแชททั้งหมด

## สรุปภาพรวม

แอป Flutter (iOS/Android/Web) + Supabase project `gowithme` (`citzutjfivstryuquxnf`, org THAITRIP)
มี 7 รอบการพัฒนาแล้ว: MVP 0.1 (รอบ 1-2) → role คนขับ/คนนั่ง (รอบ 3-4) → กฎจับคู่แบบคนขับกำหนดเอง + รูปโปรไฟล์ + แผนที่สด + รีวิว (รอบ 5) → UX แบบ Grab-lite (หน้าเดินทางรวม, การ์ดปัดเลือก, สไลด์ยืนยัน) (รอบ 6) → พุช/ปักหมุด/vibe/โหมดมืด/ความล่าช้า/เบี่ยงทาง (รอบ 7)

**Migration บน Supabase จริง:** `0001` ถึง `0016` รันลงจริงหมดแล้ว (ยืนยันตรงกับฐานข้อมูลจริงแล้ว ไม่มีไฟล์ไหนเป็นแค่ร่างค้างอยู่)

**รอบ 7 ปิดสมบูรณ์แล้ว** (QA: PASS with notes, Tester ตรวจซ้ำอิสระผ่านครบ, บั๊กที่พบระหว่างตรวจซ้ำแก้หมดแล้ว)

## เสร็จแล้ว (รอบ 1-6) — สรุปย่อ
- สมัคร/ยืนยันอีเมล/18+, โปรไฟล์, บทบาทคนขับ (ต้องลงทะเบียนรถ) / คนนั่ง สลับได้
- สร้างทริป, ค้นหา/จับคู่ (คนขับกำหนดระยะรับส่งเอง ไม่ใช่กฎ corridor แบบ Grab), แชท, จุดนัดพบ, SOS, แชร์ทริป, ผู้ติดต่อฉุกเฉิน
- รูปโปรไฟล์ (แสดงเฉพาะคู่ที่จับคู่แล้ว), แผนที่สดพร้อมไอคอนรถ/คนเดิน, ปุ่มนำทางแอปภายนอก, ระบบรีวิว/คะแนน (ต้องมีรีวิวเปิดเผย ≥3 ถึงแสดง)
- โลโก้แอป (ของผู้ใช้เอง) เป็นไอคอนทุกแพลตฟอร์ม + splash/onboarding
- หน้าเดินทางรวมแบบ Grab (แผนที่เต็มจอ + แผ่นเลื่อน 3 ระดับ + SOS ทุกระดับ), สไลด์ยืนยันแทนกล่อง dialog, การ์ดปัดเลือกเพื่อนร่วมทาง (ยกเลิกคำชวนได้ 5 วิ), บันทึกบ้าน/ที่ทำงานในเครื่อง, ปุ่มหาเพื่อนกลับบ้านหนึ่งแตะ

## รอบ 7 — สถานะสุดท้าย (2026-09-29)

| Stage | เนื้อหา | สถานะ |
|---|---|---|
| A | US-42 แจ้งเตือนพุช (โครง), US-43 snap หมุดเข้าถนน | โค้ดพร้อม รอ Firebase project ถึงจะส่งแจ้งเตือนจริงได้ |
| B | US-44 vibe/mood (ขึ้นบนการ์ดจริงแล้ว), US-45 ผู้หญิงล้วน, US-46 โหมดมืด, US-48 เสียงด่วน (TTS ใช้ได้จริง / อัดเสียงจริงยังปิดไว้) | เสร็จสมบูรณ์ ยกเว้นอัดเสียงจริง (รอ storage bucket) |
| C | US-49 จัดการความล่าช้า/ยกเลิกไม่เสียประวัติ, US-50 กฎเบี่ยงระหว่างทาง (คำนวณแม่นยำด้วย OSRM จริงแล้ว), US-47 สรุปผลกระทบ+สั่น | เสร็จสมบูรณ์ |

**Migration ที่เพิ่มระหว่างรอบ 7:** `0011a` `0011` `0012` `0013` `0014` `0015` `0016` — รันจริงครบหมด, ตรวจ SQL ผ่านทุกไฟล์ (round5/6/7, roles, dual_role, qa_round1, rls_checklist)

**ที่ตัดออกจากแผนเดิมระหว่างคุย:**
- US-45 ตัวกรอง "เฉพาะสถาบันเดียวกัน" — ตัดออก (ไม่ global เท่าผู้หญิงล้วน) คอลัมน์ `trips.same_org_only` ยังอยู่ในฐานข้อมูลแต่จงใจไม่ใช้
- US-50 รายชื่อสถานีขนส่งสาธารณะ (BTS/MRT) — ตัดออก เปลี่ยนเป็นกฎทั่วไปที่ใช้ได้ทุกปลายทางทั่วประเทศแทน

### บั๊กที่พบและแก้ระหว่างรอบ 7 (ปิดหมดแล้ว)
1. **US-50 คำนวณระยะเบี่ยงไม่แม่นยำ (เคย High):** สูตรเดิมใช้เส้นตรงคูณ 2 ซึ่งพิสูจน์แล้วว่าไม่ใช่ขอบเขตที่แม่นยำทางคณิตศาสตร์ → เปลี่ยนเป็น 2 ชั้น: (1) ตอนค้นหา/แสดงรายการ ใช้ค่าประมาณเร็วๆ เป็นตัวกรองคร่าวๆ (2) ตอนส่งคำขอจริง แอปเรียก OSRM คำนวณระยะถนนจริง ส่งให้ server ตรวจสอบด้วยสูตรที่พิสูจน์ได้ (ตามกฎสามเหลี่ยม) กันโกง — migration `0016`
2. **vibe/mood ไม่ขึ้นบนการ์ดคู่จับคู่ (เคย Medium):** `find_matches` ไม่เคยส่งค่านี้กลับมา → แก้ใน `0016` เดียวกัน ตอนนี้ขึ้นจริงแล้ว
3. **แผนที่โหมดมืดขึ้นจอเทามีลายน้ำ "API KEY REQUIRED":** CARTO (ผู้ให้บริการเดิม) เปลี่ยนนโยบายต้องมี API key → เปลี่ยนไปใช้เทคนิค "กลับสีแผนที่ปกติเป็นโทนมืด" แทน (invert + hue-rotate) ไม่พึ่งบริการภายนอกอีกเลย
4. **สูตรกลับสีแผนที่มืดคำนวณผิด (พบตอนตรวจซ้ำ):** ใส่เลขผิดตอนแปลงสูตรมาตรฐาน ทำให้สีเพี้ยนเล็กน้อย (ออกโทนส้ม/แดงผิดธรรมชาติ) → คำนวณใหม่และยืนยันด้วยการทดสอบ "สีเทาต้องออกมาเป็นสีเทา" แล้ว

5. ฝ่ายกฎหมายตรวจถ้อยคำ: รูปโปรไฟล์, รีวิว, ทะเบียนรถ, ยินยอมส่งทะเบียนไปกับ SOS/แชร์, ข้อมูลเพศ, บ้าน/ที่ทำงาน, audio note privacy

## กฎการทำงานที่ตกลงกันไว้ (สำคัญ อย่าลืม)
- **งานฐานข้อมูลทุกอย่างต้องผ่าน `/db-architect`** ก่อนเขียนโค้ด (ผู้ใช้กำหนดไว้กลางรอบ 5)
- **ห้ามรันอะไรลง Supabase จริงโดยไม่ขออนุญาตทุกครั้ง** แม้จะเป็นแค่ "ตรวจแบบ rollback" ก็ต้องขอก่อน
- ตรวจ SQL ก่อนรันจริงเสมอ: รันใน transaction ที่จบด้วย raise exception เพื่อ rollback ทั้งหมด ไม่บันทึกอะไรจริง แล้วต้องรันชุดเทสต์เก่าทั้งหมดควบด้วยเสมอ (ห้ามข้ามแม้จะดูเหมือนไม่เกี่ยวข้อง — เคยเจอ regression จริงจากการข้าม)
- Concept แอป = "กลับบ้านใกล้กัน" ไม่ใช่ Grab/บริการรับส่ง — ทุกกฎจับคู่ใหม่ต้องเช็คว่าไม่เบี่ยงกลับไปเป็นบริการรับส่งทั่วไป
- **ผลจาก subagent ที่ไม่มีเครื่องมือต่อฐานข้อมูล/เบราว์เซอร์จริง ควรตรวจทานอีกชั้นก่อนเชื่อ 100%** โดยเฉพาะเรื่องคณิตศาสตร์/สถานะ live — เคยเจอทั้งเข้าใจผิด (คิดว่า migration ยังไม่รัน ทั้งที่รันแล้ว) และจับได้ถูก (สูตรสีผิดจริง) ในรอบเดียวกัน จึงต้องตรวจสอบเองด้วยเครื่องมือจริงเมื่อทำได้ ไม่เชื่อรายงานเปล่าๆ ทั้งสองทาง
