# กลับด้วยกันมั้ย (GOWITHME)

แอป Flutter (iOS + Android) จับคู่คนที่กลับบ้านทางเดียวกัน. สถานะปัจจุบัน: Phase 1-4 P0 (auth, โปรไฟล์, สร้างทริป, จับคู่, แชท, วงจรทริป + ตำแหน่งสด, SOS/ความปลอดภัย, แชร์ทริป, PDPA). เอกสารออกแบบอยู่ที่ `docs/`.

## ต้องมี
- Flutter 3.41+ (Dart 3.11+)
- โปรเจกต์ Supabase (หรือ `supabase start` ในเครื่อง) ที่รัน migration ใน `supabase/migrations/` แล้ว

## ตั้งค่า Supabase (ห้าม commit ค่าจริง)
1. คัดลอก `env.example.json` เป็น `env/dev.json` (ไฟล์ `env/*.json` ถูก git-ignore)
2. ใส่ `SUPABASE_URL` (ต้องเป็น `https://`) และ `SUPABASE_ANON_KEY` (anon หรือ `sb_publishable_...` เท่านั้น)
3. **ห้ามใส่ `service_role` / `sb_secret_...` เด็ดขาด** — แอปจะปฏิเสธการเริ่มทำงานและแสดงหน้าแจ้งตั้งค่า
4. ใน Supabase Dashboard: Authentication > Providers > Email เปิด **Confirm email** (P-4; จำเป็นสำหรับ production) และตั้ง custom SMTP ถ้าทดสอบหลายคน

## รัน
```bash
flutter pub get
flutter run --dart-define-from-file=env/dev.json
# หรือ
flutter run --dart-define=SUPABASE_URL=https://xxxx.supabase.co --dart-define=SUPABASE_ANON_KEY=<anon>
```
ถ้าไม่ใส่ค่า (หรือค่าไม่ถูกต้อง) แอปจะเปิดหน้า "ยังไม่ได้ตั้งค่าการเชื่อมต่อเซิร์ฟเวอร์" แทนการ crash โดยไม่แสดง URL/key.

Supabase local ผ่าน http (เฉพาะ debug): เพิ่ม `--dart-define=ALLOW_INSECURE_LOCAL=true` และเปิด cleartext ฝั่ง Android เองในเครื่อง (manifest ตั้ง `usesCleartextTraffic=false` เป็นค่าเริ่มต้น)

## ฟีเจอร์ Phase 4 (สรุปสำหรับผู้ใช้/ผู้ทดสอบ)
- **แชท** (`/chats/:matchId`): Realtime ต่อการจับคู่; สถานะห้องมาจาก `chat_state` (open / blocked / trip_ended / match_closed) ถ้าไม่ใช่ open จะเป็นแถบอ่านอย่างเดียว; ส่งซ้ำได้ด้วย `client_msg_id` เดิม; จำกัดการส่งฝั่งแอป 8 ข้อความ/10 วินาที (เซิร์ฟเวอร์ 10/10 วินาที); รายงาน/บล็อกจากเมนูในห้องแชท; จุดแดงข้อความใหม่บนแท็บแชท
- **ทริปของฉัน** (`/trips`): ปัจจุบัน/ประวัติ, เริ่ม/ยกเลิก/ลบ (state machine เดียวกับ trigger ใน DB), หน้าทริปกำลังเดินทาง (`/trips/:id/active`) พร้อมปุ่ม "ถึงแล้ว", ข้อความ "ใกล้ถึงแล้ว" เมื่อห่างปลายทาง <= 300 ม.
- **ตำแหน่งสด**: ส่งให้คู่ที่จับคู่แล้วและแชทยังเปิดอยู่เท่านั้น ขณะทริปกำลังเดินทางและแอปอยู่หน้าจอ (while-in-use) อย่างน้อยห่างกัน 5 วินาที; หยุดเมื่อทริปจบ/ยกเลิก/มีการบล็อก/ถอนความยินยอม; เห็นตำแหน่งคู่บนแผนที่ (poll 20 วินาที)
- **SOS** (`/sos`): กดค้าง 2 วินาทีหรือแตะยืนยัน; แสดง 191/1669 ทันที; บันทึกเหตุการณ์ในเครื่องก่อนแล้วส่งเบื้องหลัง (id เป็น UUID ฝั่งแอป, ส่งซ้ำไม่ทำให้แถวซ้ำ), มีคิว retry เมื่อออฟไลน์; ส่งข้อความ+ลิงก์ตำแหน่ง OSM ผ่าน share sheet/SMS ไปผู้ติดต่อฉุกเฉิน
- **ผู้ติดต่อฉุกเฉิน** (`/safety/contacts`): สูงสุด 3 ราย, ลบรายสุดท้ายได้แต่มีคำเตือน, เก็บสำเนาในเครื่องให้ SOS ใช้ตอนออฟไลน์
- **แชร์ทริป**: ค่าเริ่มต้นเป็นข้อความสรุป (snapshot) ส่งแล้วเรียกคืนไม่ได้ (บอกผู้ใช้ชัดเจน); ปุ่ม "หยุดแชร์" มีเฉพาะเมื่อมีลิงก์ที่ backend สร้าง ซึ่งจะทำงานเมื่อกำหนด `--dart-define=SHARE_WEB_BASE_URL=https://...` (หน้าเว็บผู้รับเป็น P1, T4.24)
- **บัญชี/ความเป็นส่วนตัว**: `/me/settings`, `/me/settings/privacy` (สวิตช์ยินยอมตำแหน่ง, ส่งออกข้อมูลแบบ stub), `/me/settings/delete-account` (พิมพ์ "ลบบัญชี" แล้วออกจากระบบทันที), `/me/blocked`, `/policy`, `/terms`

## บทบาท คนขับ/คนนั่ง (Driver/Rider, รอบ 3)
ใช้กับทริป **รถส่วนตัว (mode = car) เท่านั้น**; เดิน/รถสาธารณะ/แท็กซี่ยังเป็น peer↔peer ไม่มีบทบาท. ต้องใช้ migration `supabase/migrations/0006_driver_rider_roles.sql` (ยังไม่ apply กับ remote: ต้องรันบน `supabase start` พร้อม `supabase/tests/roles.sql`, `qa_round1.sql`, `rls_checklist.sql` ให้ผ่านก่อน; ดู `docs/design-roles.md`).
- **เลือกบทบาท** (ขั้น 2 สร้างทริป): "ฉันขับรถ" / "ฉันขอติดรถ" ตั้งค่าเริ่มต้นตามโหมดที่ใช้อยู่ (รอบ 4, ดูหัวข้อถัดไป) เปลี่ยนได้ เลือกแล้วเปลี่ยนไม่ได้; คนขับรับได้ **1 คนเสมอ** (ไม่มีช่องกรอกที่นั่งที่ใดในแอป); คนขับต้องมี **ข้อมูลรถ** ก่อน (พาไปกรอกที่ `/me/vehicle` แล้วกลับมาโดยร่างทริปไม่หาย)
- **ข้อมูลรถ** (`/me/vehicle`): ทะเบียน/ยี่ห้อรุ่น/สี 1 ชุดต่อบัญชี + ข้อความความเป็นส่วนตัว + สวิตช์ "อนุญาตให้ส่งทะเบียนไปกับแชร์/SOS ของคนนั่ง" (ค่าเริ่มต้น **ปิด**, ไม่ผูกกับการบันทึก, ตั้งค่าโดยเซิร์ฟเวอร์). ลบไม่ได้ขณะมีทริปคนขับที่ยังไม่จบหรือมีการจับคู่ (`GWM_VEHICLE_IN_USE`). ป้าย "ข้อมูลรถแจ้งโดยคนขับ ยังไม่ผ่านการตรวจสอบ" ทุกจุดที่แสดง. รุ่น/สี/ทะเบียนแสดงในแอปให้คนนั่งที่ **ตอบรับแล้ว** เท่านั้น (ไม่มีในผลค้นหา/คำขอ); คนนั่งที่กดขึ้นรถแล้วยังเห็นต่อแม้การจับคู่สิ้นสุด (Q-2)
- **ค้นหา/คำขอ**: คนขับเห็นเฉพาะคนนั่ง และกลับกัน (บังคับที่ backend, แอปกรองซ้ำ); การ์ดมีป้ายบทบาท + "รับได้ 1 คน"; ส่งคำขอได้ทั้งสองฝ่าย ตอบรับได้เฉพาะผู้รับ; ตอบรับแล้วคำขออื่นของทั้งสองทริปถูกปิดแบบเป็นกลาง และทริปหายจากการค้นหา
- **จุดรับ** (`/matches/:id/pickup`): คนขับเสนอก่อน คนนั่งยืนยันหรือเสนอใหม่; ระยะเบี่ยงจากเส้นทางคนขับ (`match.pickup_max_deviation_m`, 500 ม.) เป็น **คำเตือนเท่านั้น** ไม่บล็อก; เซิร์ฟเวอร์ตอบเป็น boolean (ไม่บอกระยะ) ส่วนคนขับเห็นระยะเมตรที่แอปคำนวณจากเส้นทางของตัวเอง
- **ขึ้นรถแล้ว / ไม่มาตามนัด / ยกเลิก**: คนนั่งกด "ขึ้นรถแล้ว" ได้เมื่อทั้งสองทริปเริ่มแล้ว (หลังนั้นหยุดส่งตำแหน่งให้คนขับ, ยกเลิกการจับคู่ไม่ได้, คนขับยกเลิกทริปไม่ได้ `GWM_ALREADY_BOARDED` แต่กด "ถึงแล้ว" ได้); คนขับกด "คนนั่งไม่มาตามนัด" ได้ก่อนคนนั่งขึ้นรถ (ไม่มี timer/โทษ, เหตุผลเป็นข้อมูลภายใน); ข้อความระบบเป็นกลาง
- **แชร์/SOS**: ข้อความของคนนั่งมีชื่อคนขับเสมอ และ **ทะเบียนอย่างเดียว** เมื่อคนขับอนุญาต (ไม่มีรุ่น/สี); ของคนขับมีทะเบียนของตนเอง + ชื่อคนนั่ง; แสดงตัวอย่างว่า "มี/ไม่มีทะเบียน" ก่อนส่ง และตรวจสถานะอีกครั้งก่อนส่ง (ถ้าเปลี่ยนจะให้ดูตัวอย่างใหม่); SOS ไม่รอ/ไม่ถูกขวางถ้าโหลดสถานะไม่ได้; snapshot ทะเบียนใน `sos_events` เติมโดยเซิร์ฟเวอร์ (แอปไม่ส่ง)
- **แจ้งเตือนเมื่อการจับคู่สิ้นสุดระหว่างเดินทาง** (Q-7): Realtime `matches` + รีเฟรชทันทีเมื่อกลับเข้าแอป -> แบนเนอร์บนทุกหน้า (SOS / แชร์ทริป / ถึงแล้ว / ยกเลิกทริปของฉัน) และเรียก `LocalNotifier` (`lib/core/notify/local_notifier.dart`; ตอนนี้เป็น no-op/debug log, ข้อความเป็นกลางไม่มีทะเบียน/ชื่อ/ตำแหน่ง, เสียบ flutter_local_notifications ภายหลังได้โดยไม่แก้ตรรกะ). **ข้อจำกัด: ไม่มี remote push ใน MVP ผู้ใช้ที่ปิดแอปอาจไม่เห็นการแจ้งเตือนจนกว่าจะเปิดแอป**
- **ก่อนเริ่มเดินทาง** (ทริป car ที่มีคู่แล้ว): แจ้งครั้งแรกว่า "คู่ที่จับคู่แล้วเห็นตำแหน่งสดของคุณ"; คนขับที่ยังไม่ตกลงจุดรับเห็นคำเตือนที่ไม่ขวาง
- **ไม่มีเงินในแอป** และไม่ใช้คำเชิงพาณิชย์ (ค่าโดยสาร/ค่าบริการ/รับจ้าง) ในข้อความใดของแอป; ฝ่ายกฎหมายต้องทบทวนถ้อยคำก่อนเปิดใช้จริง (T6.21)
- **เดโม**: ในสารบัญ `/demo` หัวข้อ "บทบาท" สลับเป็นคนขับ/คนนั่ง/เดิม (รีเซ็ตทริป คำขอ ข้อมูลรถ) พร้อมปุ่มจำลองอีกฝ่าย (เริ่มเดินทาง, เสนอจุดรับ, ขึ้นรถ, ยกเลิกการจับคู่) และสวิตช์ทะเบียน

## ลงทะเบียนคนขับ + สลับโหมด + โทนสี 2 ชุด (Dual role, รอบ 4)
ทุกบัญชีเริ่มเป็นคนนั่ง; ต้อง **ลงทะเบียนเป็นคนขับ** (ข้อมูลรถ 3 ช่อง + ติ๊กรับรองตนเอง) จึงสร้างทริปแบบคนขับและสลับโหมดคนขับได้ **เป็นการแจ้งเอง แอปไม่ตรวจสอบใบขับขี่/รถ** และไม่เก็บเลขที่หรือรูปใบขับขี่ (เก็บเฉพาะว่ารับรองแล้ว + เวลา + เวอร์ชันข้อความ ที่ฝั่ง server). ต้องมี migration `0008_driver_registration.sql` บน backend จึงจะใช้กับ Supabase จริง (ดู `docs/design-roles.md` §11).
- **ลงทะเบียน** `/me/driver/register` (ทางเข้า: แท็บ "ฉัน" > การ์ด "มีรถ? ลงทะเบียนเป็นเจ้าของทริป", ตัวเลือก "ฉันขับรถ" ที่ล็อกในฟอร์มสร้างทริป): แจ้งก่อนว่า *แจ้งเอง ยังไม่ผ่านการตรวจสอบ / รับได้ 1 คน / ไม่มีเงินในแอป*, เติมข้อมูลรถเดิมให้ (ต้องรับรองใหม่ทุกครั้ง, ช่องรับรองไม่ติ๊กไว้ล่วงหน้า), ส่งครั้งเดียวผ่าน `register_driver` (atomic). ระหว่างรอ ปุ่มปิด/ปุ่มส่งปิด; สำเร็จแล้ว **เสนอ** ให้สลับ (ไม่สลับเอง).
- **สลับโหมด 1 แตะ**: แถบใต้แอปบาร์ของ 5 แท็บ = ป้าย "โหมดคนนั่ง/โหมดคนขับ" (ไอคอน + ข้อความ + สี) + ปุ่ม "สลับเป็น...". สลับเป็นคนขับต้องรอ server (โทนไม่เปลี่ยนจนกว่ายืนยัน, ออฟไลน์ = แจ้งทันที); สลับกลับเป็นคนนั่งได้เสมอ (ออฟไลน์ก็ได้ เก็บคิวซิงก์ไว้). บัญชีที่ยังไม่ลงทะเบียนเห็นแค่ป้าย (ไม่มีปุ่มชวน, คำตัดสิน Q-D3). การ์ด "บทบาทของฉัน" ในแท็บ "ฉัน" มีสวิตช์แบบแบ่งช่อง + ข้อมูลรถ + "ยกเลิกการลงทะเบียนคนขับ".
- **ยกเลิกการลงทะเบียน**: dialog ยืนยัน (ปุ่มปลอดภัยก่อน); ถ้ามีทริปคนขับที่ยังไม่จบหรือการจับคู่ที่ตอบรับแล้ว จะแสดงเหตุผลพร้อมทางไป "ทริปของฉัน" (ตรวจในเครื่องก่อน แล้ว server ตัดสินซ้ำ). ข้อมูลรถยังเก็บไว้ (เห็นเฉพาะเจ้าของ) ลบได้หลังยกเลิกเท่านั้น.
- **โทน 2 ชุด**: `riderTheme` (หน้าตาเดิม) และ `driverTheme` (พื้นกรมท่าเข้ม + amber) จาก token ชุดเดียวกัน (`lib/core/theme/tone.dart`, `app_theme.dart`); หน้าระดับแอปใช้ตามโหมดที่ใช้อยู่ ส่วนหน้าทริปรถ (รายละเอียด/กำลังเดินทาง/แชร์/SOS/จับคู่/แชท) ใช้โทนตาม **role ของทริป** เสมอ (`TripRoleTone`) เส้นทางบนแผนที่ก็เช่นกัน. SOS เป็นสีแดงเดิมทั้งสองโทน. โหมดล่าสุดจำในเครื่องต่อบัญชี (ไม่กระพริบโทนผิดตอนเปิดแอป) แต่ server เป็นความจริงเสมอ; ไม่สอดคล้อง (เช่น ยกเลิกลงทะเบียนจากเครื่องอื่น) = กลับเป็นคนนั่ง + แจ้งครั้งเดียว.
- **ฟอร์มสร้างทริป**: role เริ่มต้นตามโหมดที่ใช้อยู่ (ข้อความ "ตั้งไว้ให้ตามโหมดที่คุณใช้อยู่ เปลี่ยนได้"); ถ้าผู้ใช้เลือกเอง (`roleTouched`) จะไม่ถูกเขียนทับ; ไปลงทะเบียนแล้วกลับมาข้อมูลฟอร์มไม่หาย (ฉบับร่างอยู่ใน provider).
- **เดโม** (`/demo` หัวข้อ "โหมดคนขับ/คนนั่ง และการลงทะเบียนคนขับ"): บัญชีคนนั่งล้วน / สองบทบาท, จำลองยกเลิกลงทะเบียนจากอุปกรณ์อื่น, จำลองออฟไลน์, จำลอง server ปฏิเสธการลงทะเบียน. การยกเลิกลงทะเบียนถูกปฏิเสธเมื่อมีทริปคนขับ (ฉากคนขับ) และสำเร็จหลังทริปจบ.

## รอบ 5: รูปโปรไฟล์, แผนที่สด, นำทาง, รีวิว, corridor matching, โลโก้
ต้องมี migration `0009_corridor_matching_avatars_ratings.sql` บน backend จึงจะใช้กับ Supabase จริง (ร่าง ยังไม่ apply; ดู `docs/design-roles.md` §12). **ทุกอย่างดูได้ใน DEMO_MODE** (`/demo` หัวข้อ "รอบ 5").
- **รูปโปรไฟล์** (`/me/photo`, จากแท็บ "ฉัน" หรือ "แก้ไขโปรไฟล์"): เลือกจากคลังภาพ/กล้อง (เว็บ = ไฟล์ของเบราว์เซอร์) -> ย่อเป็นสี่เหลี่ยมจัตุรัส <= 512 px JPEG q80 **ตัด EXIF/GPS ทั้งหมดในเครื่อง** (`lib/features/avatar/domain/avatar_processing.dart`) -> อัปโหลดไป bucket `avatars` ที่ `<uid>/avatar.jpg` -> `set_my_avatar`. แสดงเฉพาะคู่ที่จับคู่ตอบรับแล้ว (หน้าจับคู่, แชท, แผนที่สด, รายการแชท) ผ่าน **signed URL อายุ 120 วินาที** (แคชในแอป 90 วินาที) พร้อมตัวอักษรย่อสำรองทุกกรณี; ผลค้นหา/คำขอที่รอ **ไม่ขอรูปเลย**. ลบรูป, รายงานรูปจาก sheet ดูรูป (`/report/photo/:userId`). ไม่ log path/URL.
- **แผนที่สด** (`/matches/:id/live`, ปุ่ม "ดูแผนที่ร่วมกัน" ในหน้าทริปกำลังเดินทางและหน้าจับคู่): คนขับ = ไอคอนรถ (หมุนตามทิศเมื่อขยับ >= 15 ม.), คนนั่ง = หมุดคน; เลื่อนสมูทระหว่างตำแหน่งที่ได้ทุก 15 วินาที (ไม่คาดเดาล่วงหน้า, กระโดด > 2 กม. หรือ "ลดการเคลื่อนไหว" = ย้ายทันที); เกิน 45 วินาทีขึ้น "อัปเดตเมื่อ N วินาทีที่แล้ว" + ไอคอนเก่า; ปุ่มตามตำแหน่ง/กลับมาที่ตำแหน่ง/ดูทั้งสองฝ่าย/ซูม; ETA จาก OSRM (คำนวณไม่เกิน 1 ครั้ง/45 วินาที, สำรองเส้นตรง "(ไม่แม่น)"); ปุ่ม "ข้อมูลแบบข้อความ" สำหรับ screen reader. **ไม่แสดงจุดลงของคนนั่งให้คนขับ** (ตกลงผ่านแชทด้วยข้อความสำเร็จรูป).
- **นำทาง** (US-24): ปุ่มเดียวตามสถานะ "นำทางไปจุดรับ" (ปิด + เหตุผลถ้ายังไม่ตกลงจุด, ซ่อนเมื่ออยู่ห่างจุดรับ <= 50 ม.) หรือ "นำทางไปปลายทาง"; แจ้งครั้งแรกว่าพิกัดถูกส่งให้แอปแผนที่; เปิด Google Maps / Apple Maps (iOS) / เว็บผ่าน `url_launcher` ส่งเฉพาะพิกัดเป้าหมาย.
- **จับคู่รถแบบ neighbourhood** (US-21 ฉบับสุดท้าย): จุดเริ่มห่างกัน ≤ 2 กม., ปลายทางของคนนั่งอยู่ภายใน **ระยะรับส่งของทริปคนขับ** (`trips.max_dropoff_m` 500–5000 ม. ทีละ 100 ค่าเริ่มต้น 2000; ตั้งตอนสร้างทริปคนขับด้วยแถบเลื่อน + ปุ่มลัด 1/2/3/5 กม. หรือแก้ในหน้าทริป ล็อกเมื่อมีคำขอรอ/จับคู่แล้ว), เส้นทางซ้อน ≥ 40%, เวลาห่าง ≤ 30 นาที. การ์ดฝั่งคนนั่งแสดง "คนขับรับส่งได้ไม่เกิน X จากปลายทางของเขา"; คนขับไม่เห็นปลายทางของคนนั่ง (`approx_dest_*` เป็น NULL). ไม่มีข้อความ/ตัวเลขระยะเบี่ยงอีกต่อไป. คำอธิบายเมื่อไม่พบผล = `get_match_hint` (has_results / none_found / far_destination / far_origin หมวดเดียว ไม่มีตัวเลข).
- **รีวิว** (US-26, P1): แจ้งชวนรีวิว 1 ครั้งหลังถึงที่หมาย (sheet), ให้ดาว/แท็ก/ความเห็น <= 200, รีวิวแบบ blind (แก้ไม่ได้), `/me/reviews` ดูที่ได้รับหลังเปิดเผย + รายงาน; **ค่าเฉลี่ยแสดงเมื่อมีรีวิวเปิดเผย >= 3 เท่านั้น มิฉะนั้นซ่อนทั้งส่วน**.
- **โลโก้/ไอคอน**: ครอปจาก `assets/branding/logo_source.png` ด้วย `python tool/make_logo.py` (อ่าน `assets/branding/README.md`): iOS full-bleed ไม่โปร่งใส, Android adaptive + legacy, เว็บ favicon/PWA/maskable, ใน-แอป splash/onboarding/sign-in.

ไม่แตะ `supabase/`; migration `0011a`-`0015` (รวมถึง `0014_lateness_detour.sql` ของขั้นนี้) apply ขึ้น live แล้วก่อนเริ่มงานขั้นนี้
- **ตรวจจับความล่าช้า + ยกเลิกไม่เสียประวัติ** (US-49): ระหว่างเดินทางไปนัดพบคู่จับคู่รถ (จับคู่แล้ว ยังไม่ขึ้นรถ) ถ้าเลยเวลานัดเกิน 10 นาที หรือระยะทางตรงถึงจุดนัดไม่ลดลงเลย 3 ครั้งติดใน ~5 นาที จะขึ้นการ์ดสองตัวเลือก "รอต่ออีก 10 นาที" / "ยกเลิกการเดินทาง (ไม่เสียประวัติ)" บนทั้งสองฝั่ง; กด "ยกเลิก" เซิร์ฟเวอร์จะตรวจซ้ำเองเสมอ (ไม่เชื่อไคลเอนต์) ถ้ายังไม่เข้าเงื่อนไขจริงจะขึ้นข้อความอธิบายสุภาพแทนที่จะ error; อีกฝ่ายได้รับแจ้งเตือนผ่านช่องเดิม ไม่กล่าวโทษฝ่ายใด; การ์ดหลบให้สไลด์ถึงที่หมายเสมอเมื่อใกล้จบทริปแล้ว
- **ระยะเบี่ยงที่ยอมรับได้เพิ่มเติม** (US-50): ในฟอร์มสร้างทริปของคนขับ มีสไลเดอร์ใหม่แยกจากระยะรับส่งเดิม (200 ม.–2 กม. ขยับทีละ 100 ม. ค่าเริ่มต้น 500 ม.) สำหรับ "ระยะทางถนนเพิ่มขึ้นจริงไป-กลับ" ที่ยอมให้เบี่ยงไปส่งคนนั่งที่ปลายทางอยู่นอกเส้นทางเล็กน้อย — เป็นทางเลือกที่สองคู่ขนานกับระยะรับส่งเดิม (จับคู่ได้ถ้าผ่านเงื่อนไขใดเงื่อนไขหนึ่ง) ใช้ได้กับปลายทางคนนั่งทุกที่ผ่าน flow ค้นหา/ปักหมุดเดิม ไม่มี UI ใหม่สำหรับเลือกสถานี; ล็อกแก้ไม่ได้เมื่อมีคำขอ/จับคู่ค้างอยู่เหมือนระยะรับส่งเดิม
- **ผลกระทบร่วม + สติกเกอร์ขอบคุณ + สัมผัสสั่น** (US-47): หลังสไลด์ถึงที่หมายสำเร็จ (เมื่อมีคู่จับคู่ตอบรับ) จะเห็นการ์ดสรุป "คุณและ [ชื่อเล่นเพื่อน] ร่วมกันลดก๊าซคาร์บอนไดออกไซด์ไป ~X kg CO₂" พร้อมป้าย "(โดยประมาณ)" และ disclaimer หนึ่งบรรทัด ตามด้วยปุ่มส่งสติกเกอร์ขอบคุณ 4 แบบสำเร็จรูป (ส่งผ่านช่องแชทปกติ ไม่มีช่องพิมพ์อิสระ); สัมผัสสั่นเบาเมื่อลากการ์ดผู้สมัคร และสั่นหนักเมื่อสไลด์ยืนยันถึง 95% — ทั้งสองจุดเคารพการตั้งค่าลดการเคลื่อนไหว/สั่นของอุปกรณ์เสมอ (ปิดอัตโนมัติเมื่อผู้ใช้ตั้งค่าไว้)
- Demo: หน้า hub หมวด "รอบ 7 (ขั้น C)" (จำลองเข้า/ไม่เข้าเงื่อนไขล่าช้า, ตั้งระยะเบี่ยงแคบ/กว้างแล้วดูรายการค้นหาเปลี่ยน, เปิดหน้าถึงแล้วเพื่อดูการ์ดผลกระทบร่วม+สติกเกอร์)

## รอบ 7 — precise detour + vibe/mood fix (Dart)
ไม่แตะ `supabase/`; migration `0016_precise_detour.sql` ถือว่า apply ขึ้น live แล้วก่อนเริ่มงานนี้ (แก้ BUG-R7-03/BUG-R7-01 จาก `docs/test-report.md`)
- **ระยะเบี่ยงแม่นยำจาก OSRM จริงตอนกด "ขอติดรถ"** (US-50): เมื่อคนนั่งเลือกคนขับที่เข้าเกณฑ์ได้เฉพาะทาง "ระยะเบี่ยงที่ยอมรับได้" (ไม่ใช่ทางระยะรับส่งปกติ) แอปจะคำนวณระยะเบี่ยงจริงผ่าน OSRM (ต้นทาง→ปลายทางคนขับ, ต้นทาง→ปลายทางคนนั่ง, ปลายทางคนนั่ง→ปลายทางคนขับ) แล้วส่งไปพร้อมคำขอให้เซิร์ฟเวอร์ตรวจสอบอีกชั้น (กันโกง); ถ้า OSRM ล้มเหลว/หมดเวลา จะขึ้นข้อความ "คำนวณระยะเบี่ยงไม่สำเร็จ ลองใหม่อีกครั้ง" โดยไม่ส่งคำขอไปก่อนแทนการเดาค่า
- **ชิป vibe/mood บนการ์ดคู่จับคู่ใช้งานได้จริงแล้ว** (US-44): แก้ช่องโหว่ที่การ์ดในรายการค้นหา/หน้ารายละเอียดผู้สมัคร parse ข้อมูล vibe/mood ไว้แล้วแต่ไม่เคยมีข้อมูลไหลมาถึง — ตอนนี้ปรากฏจริงเมื่อคู่จับคู่ตั้งค่าไว้และยังไม่หมดอายุ 24 ชม.
- Demo: หน้า hub หมวด "รอบ 7 (ขั้น D)" — สวิตช์เพิ่มผู้สมัคร "แนน" ที่เข้าเกณฑ์ผ่านระยะเบี่ยงเท่านั้น (ลองกด "ขอติดรถ" เพื่อดูการคำนวณ OSRM จริงในเดโม), ปุ่มจำลองบริการ OSRM ล้มเหลวครั้งถัดไป, ลิงก์ไปหน้ารายละเอียดแนนเพื่อดูชิป vibe/mood

## Demo mode (ไม่ต้องมี Supabase)
ข้อมูลทั้งหมดเป็นข้อมูลสมมติในหน่วยความจำ (กรุงเทพฯ) ผู้ใช้ล็อกอินอยู่แล้ว ข้ามขั้นตอนตั้งค่าโปรไฟล์. เส้นทางเป็นเส้นตรงจำลอง (ไม่ใช่เส้นทางถนนจริง) มีป้าย "DEMO" ด้านบน แตะเพื่อเปิดสารบัญทุกหน้า (`/demo`).

```bash
# Chrome
flutter run -d chrome --dart-define=DEMO_MODE=true
# เว็บเซิร์ฟเวอร์ (เปิดจากเครื่องอื่น/iPhone ผ่าน Safari ที่ http://<IP เครื่อง>:8080)
flutter run -d web-server --web-hostname 0.0.0.0 --web-port 8080 --dart-define=DEMO_MODE=true
# Android emulator
flutter run -d <emulator-id> --dart-define=DEMO_MODE=true
# build เว็บ
flutter build web --dart-define=DEMO_MODE=true
```
ในเดโมดูฟีเจอร์ Phase 4 ได้ครบ: แท็บ **แชท** (พิมพ์ส่งแล้วคู่ตอบอัตโนมัติ), **ทริปของฉัน** (กด "เริ่มเดินทาง" แล้วตำแหน่งจำลองเดินไปถึงปลายทางใน ~1 นาที เห็นตำแหน่งคู่และข้อความ "ใกล้ถึงแล้ว"), ปุ่ม **SOS** (สวิตช์ "จำลองออฟไลน์" ในสารบัญเดโมทำให้เห็นคิวส่งซ้ำ), ผู้ติดต่อฉุกเฉิน, แชร์ทริป (เดโมจำลองว่ามีหน้าเว็บแชร์เพื่อให้เห็นปุ่มหยุดแชร์), ตั้งค่า/ความเป็นส่วนตัว/ลบบัญชี. การโทร/SMS/share sheet ในเดโมแสดงเป็นแถบข้อความด้านล่างแทนการเปิดแอปจริง; ในสารบัญ (`/demo`) มีปุ่มบังคับสถานะแชท (blocked / trip_ended / match_closed).

## ตัวแปร `--dart-define` เพิ่มเติม
| ชื่อ | ความหมาย |
|---|---|
| `SHARE_WEB_BASE_URL` | URL หน้าเว็บผู้รับลิงก์แชร์ (`https://...`). ว่าง = ไม่สร้างลิงก์ มีแค่ข้อความ snapshot |
| `DEMO_MODE` | เปิดโหมดเดโม (ไม่เชื่อม Supabase) |
| `ROAD_SNAP_MAX_DEVIATION_M` | (รอบ 7) ระยะเบี่ยงสูงสุด (เมตร) ที่ยอมรับผลลัพธ์ OSRM `nearest` ก่อนเสนอจุดรับ ค่าเริ่มต้น 40 |

iPhone (ไม่ต้องมี Mac): รันแบบเว็บเซิร์ฟเวอร์แล้วเปิดใน Safari (เครื่องอยู่ Wi-Fi เดียวกัน) กด "เพิ่มไปยังหน้าจอโฮม" ได้. ไม่ใส่ `DEMO_MODE` แอปทำงานตามปกติ ไม่มีโค้ดเดโมทำงานใน production. ลบฟีเจอร์: ลบ `lib/demo/` (ดู `docs/dev-notes.md`).
